Earlier when automating tasks, we hard coded the process of taking the input from A to B. As we discovered more edge cases, we add more and more complexity to the code, using bunch of if/else statements.

One thing that is still well defined is the type of input we are gonna get and the output we want to produce.

Here is where AI software development is different, the input is fuzzy meaning we know it will be a string, but we don't know what the string will represent. This also means that the transformations that we need to do is also fuzzy and the outputs will also be fuzzy.

![[Pasted image 20250116120650.png]]

Here is where agentic approach comes in, instead of having a collection of rules in the process, we will have a collection of agents each of which does a specific task. 

For example consider the task of converting lead data from website to sales team. Earlier all we could do is have some checks about the type of user and based of it we would decide how to approach the customer.

Using agentic approach we can have an agent do research about the customer and the organisation that the user belongs, another can draw out comparisons between current customer's and this new customer that visited the website, another agent could set the score which we can use to prioritise the users, and finally an agent that will generate talking points that we can use to convert the visitor to customer.

## AI Agents

When we talk to llm's like chatgpt, we see that the more instructive our prompt the better it performs, but if still the response was not good enough, then we can ask it to correct it self by pointing out some points that we didn't like in the previous response. 

We quickly realise that through interactions we get better results. This means that when making automation through AI, we need to implement this kind of interaction.

An AI Agent is simply, making llm's reason and ask questions, then making llm's to answer these questions, then using llm's to verify the quality of the answers and making it better.

Hence when we give a task to an agent, it will give an answer that will not necessarily be the first answer that it came up with, but it can then think through and optimise the answer up to a point that satisfies itself.

But we can do more, we can give the agent's tools that they can use in order to interact with outside world, for example we can give me tools like data retrieval from internet, tools like code runner etc.

## Key Elements Of AI Agents

There are 6 key elements that make an AI agent perform well, they are
- Role Playing,
- Focus
- Tools
- Cooperation
- Guardrails
- Memory

#### Role Playing

It is seen that llm's perform better if they are role playing. Assigning roles to llm's makes them give better response according to the role assigned. For example, look at the two different prompts we give to chatgpt for the same question, one with role playing and another without role playing.

![[Pasted image 20250119093606.png]]

If you run these two prompts you will see the differences in response that chatgpt gives. Now it is not necessary that one is better than the other, but we can see that with roles we can make llm's return certain type of response.

Hence we should be mindful of role's when creating AI Agents, more precisely we can assign them **Roles**, **Goals**, **Backstory**.

#### Focus

The next important thing is that an agent must be focused, meaning we should not give them too many tasks, or too much information, or too many tools. Even though the llm's are getting better and have better context window now, but still providing too many tasks/information leads to more chances of llm losing out important information or hallucinating.

Hence, we must divide a task into multiple more focused tasks and create agents for each specific task. We must also carefully choose what tools to give to agents and not load them we too many tools.

#### Tools

Allowing agent's tools like interned information retrieval, code runner etc can be very powerful and make them actually act like an employee rather than just a chat completion tool.

#### Collaboration

Agent's will produce better result if then can talk to each other, delegate tasks, take feedback from other agents. This is necessary to mimic the interaction that we have will chat bots like chatgpt where we give feedback to make it give better result.

#### Guardrails

Guardrails help agent's from hallucinating or being stuck in a infinite request response loop or keep using the same tool again and again or if they take a lot of time to generate a response.

#### Memory

Memory can make immense on our agents, if anything it can make more impact than all the other element's combined. The ability to remember what it has done in the past and use it to inform new decisions and new executions.

In crew ai there are three types of memory,
- **Short Term Memory:** this is the memory that lives only during the crew's execution, it is important because as different agent's try to accomplish different tasks, they store their learning in this memory. This memory is shared across all the agents meaning that one agent can tap into the short term memory of another agent.
- **Long Term Memory:** it lives even after the crew finished its execution, it lives in a database. This can be used in any future task or used to help agent in self critic and help improve its future responses.
- **Entity Memory:** is also short memory of different entities in the discussion. This will help it get broader idea of what the discussion is about.
