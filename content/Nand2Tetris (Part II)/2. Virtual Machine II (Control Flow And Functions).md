### Program Control

So far, the vm code that we have seen executed in linear fashion i.e. the commands were executed in the order there are present in the vm file. This type of programs are not very useful when building large sophisticated software.

Every modern high level language have concept of conditional statements (i.e. `if/else`, loops (i.e. `for/while`), all of these are commands that help change the program control flow i.e. instead of being linear, it can have any type of path as shown below.

The expression in high level language looks very much like the formula, and this is very much like how we think about the formula.

The `sqrt or power or disc` are functions that are not native commands of the programming language. They are functions written by the programmer, they act as an extension of the language.

The number of features that a programming language can provide out of the box are very limited, but the extensions can be infinite. This is what makes modern programming languages to powerful and help programmers to write very sophisticated software(s).

This functionality is achieved by program control commands which allow the program execution to be non linear i.e. it can go-to, jump, skip commands as the programmer wishes.

### Branching

Branching is simply, jumping to some instruction from a given instruction with or without condition. This helps us to have `if/else` statements, `loops` in our programs, which make them very powerful.

Below we have a simple high level program that computes multiplication between two integers and its corresponding vm code.

![[Pasted image 20250316183700.png]]

We see that there are two types of `go-to` commands in this vm code. The first is `if-goto` which only jumps if the top current value in the stack is `true`, this requires us to push the condition to the stack just before the `if-goto` command. The other command is `goto` which will jump to `label` unconditionally.

### Functions Abstraction

Functions are pieces of code, that could be used in the program just like any other primitive operators i.e. they have the same look and feel like other primitive operators of the language (i.e. `sub, add, ...`)

![[Pasted image 20250316194950.png]]

The rules of the game is as follows,
- If the function expects `n` number of arguments, then we push these arguments into the stack.
- After the argument has been pushed, then we call the function.
- Once the function execution is completed, the arguments in the stack will be replaced with the return value of the function.

If we look at how the function works from the stack's perspective, then we see that the function works in the same way as operators like `add, sub, gt ...`.

The syntax for function definition is `function function_name x` where `x` is the number of **local** variables that the function uses (the use for this will become clear later).
##### Functions in the VM Language: Executing

In the image below, we have a `main` function that in it's execution call's the `mult` function (the same `mult` function that we showed earlier). In the function terminology, the function `main` here is called **Caller** and the function `mult` is called the **Callee**.

![[Pasted image 20250317195216.png]]

The following important happened when the function `main` get's executed,
- The first new thing is when the instruction `4` is reached. The line `4` in the main function says that it want's to call the function `main` and the number at the end specifies how many arguments were pushed into the stack before calling this function (`2` in this case with values `8 and 5`).
- Now the function `mult` starts executing, it gets the arguments in the arguments segment, it gets a local segment of capacity that is written in function definition with each value initialised to `0`. Finally it get's an empty stack.
- The `mult` function continues execute till the condition to end loop is met, then at line number `20` we push the value store in `local 0` into the stack and then we return. When a function returns, the top value stored in it's stack is considered to be the return value.
- Then we get back to the `main` function where the argument's are now replaced with the return value and the function continues to execute.
