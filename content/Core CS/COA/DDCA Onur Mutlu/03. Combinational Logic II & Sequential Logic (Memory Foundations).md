### 1.2 Recap of Combinational Foundations
Before introducing new functional units, we recall the fundamental principles established in Lecture 2:

- **Functional Specification via Boolean Equations**: Boolean algebra provides a rigorous mathematical contract specifying the exact input-output behavior of a combinational block.
- **Canonical Representations**:
  - **Sum of Products (SOP)**: Expresses a function as an OR sum of active minterms ($\sum m_i$), leading directly to a uniform **two-level AND-OR logic** structure.
  - **Product of Sums (POS)**: Expresses a function as an AND product of maxterms ($\prod M_i$), leading to a uniform **two-level OR-AND logic** structure.
- **Modular Combinational Blocks**:
  - **Decoder ($N \to 2^N$)**: An "input pattern detector" that asserts exactly one output line corresponding to the $N$-bit binary pattern applied to its inputs. Essential for memory address decoding and instruction opcode decoding.
  - **Multiplexer ($N \to 1$)**: A data selector that routes one of $N$ input data lines to the output based on a $\log_2 N$-bit select signal.
  - **Lookup Tables (LUTs)**: Multiplexers can implement arbitrary Boolean functions by storing truth-table output values in configuration memory cells (SRAM) feeding the multiplexer inputs—the universal foundation of modern Field-Programmable Gate Arrays (FPGAs).

# 2. Binary Arithmetic & The Full Adder

Arithmetic computation is a defining requirement of general-purpose computers. All higher-level mathematical operations (subtraction, multiplication, division) fundamentally rely on binary addition.

### 2.1 Principles of Binary Addition
Binary addition operates identically to familiar decimal addition:
- Operands are processed **from right to left** (least significant bit to most significant bit).
- Addition proceeds **column by column**.
- Each column produces a **Sum ($S_i$)** bit and a **Carry-out ($C_{i+1}$)** bit that propagates into the next higher-order column.

```
      Column Addition:
         C_n   C_{n-1}  ...   C_2   C_1   C_0 (Cin = 0)
               a_{n-1}  ...   a_2   a_1   a_0
         +     b_{n-1}  ...   b_2   b_1   b_0
         ─────────────────────────────────────
         C_n   S_{n-1}  ...   S_2   S_1   S_0
```

### 2.2 The 1-Bit Full Adder
A **Full Adder** is a combinational circuit that adds three 1-bit inputs:
- Two operand bits: $A_i$ and $B_i$
- One carry-in bit from the previous lower-order column: $C_i$ (or $Carry_i$)

It produces two 1-bit outputs:
- **Sum ($S_i$)**: The current column's sum bit.
- **Carry-out ($C_{i+1}$)**: The carry bit passed to the next higher-order column.

#### Full Adder Truth Table
| Row | $A_i$ | $B_i$ | $C_i$ ($Carry_i$) | $C_{i+1}$ ($Carry_{i+1}$) | $S_i$ | Minterm |
| :---: | :---: | :---: | :---: | :---: | :---: | :---: |
| 0 | 0 | 0 | 0 | **0** | **0** | $m_0 = \overline{A_i}\,\overline{B_i}\,\overline{C_i}$ |
| 1 | 0 | 0 | 1 | **0** | **1** | $m_1 = \overline{A_i}\,\overline{B_i} C_i$ |
| 2 | 0 | 1 | 0 | **0** | **1** | $m_2 = \overline{A_i} B_i \overline{C_i}$ |
| 3 | 0 | 1 | 1 | **1** | **0** | $m_3 = \overline{A_i} B_i C_i$ |
| 4 | 1 | 0 | 0 | **0** | **1** | $m_4 = A_i \overline{B_i}\,\overline{C_i}$ |
| 5 | 1 | 0 | 1 | **1** | **0** | $m_5 = A_i \overline{B_i} C_i$ |
| 6 | 1 | 1 | 0 | **1** | **0** | $m_6 = A_i B_i \overline{C_i}$ |
| 7 | 1 | 1 | 1 | **1** | **1** | $m_7 = A_i B_i C_i$ |

### 2.3 Mathematical Derivation & Boolean Simplification

#### 1. Derivation of Carry-Out ($C_{i+1}$)
Examining the truth table reveals a vital behavioral insight:
- $C_{i+1} = 1$ whenever **at least two of the three inputs are 1**.
- Therefore, Carry-out is a **3-input Majority function** ($\text{MAJ}$).

From the canonical SOP form:
$$
C_{i+1} = \sum m(3, 5, 6, 7) = \overline{A_i} B_i C_i + A_i \overline{B_i} C_i + A_i B_i \overline{C_i} + A_i B_i C_i
$$
Applying Boolean simplification using the idempotent rule ($X + X = X$) to replicate $A_i B_i C_i$:
$$
\begin{aligned}
C_{i+1} &= (\overline{A_i} B_i C_i + A_i B_i C_i) + (A_i \overline{B_i} C_i + A_i B_i C_i) + (A_i B_i \overline{C_i} + A_i B_i C_i) \\
&= (\overline{A_i} + A_i) B_i C_i + (\overline{B_i} + B_i) A_i C_i + (\overline{C_i} + C_i) A_i B_i \\
&= B_i C_i + A_i C_i + A_i B_i
\end{aligned}
$$
$$
\mathbf{C_{i+1} = A_i B_i + A_i C_i + B_i C_i = \text{MAJ}(A_i, B_i, C_i)}
$$
#### 2. Derivation of Sum ($S_i$)
Examining the truth table reveals that $S_i = 1$ whenever an **odd number of inputs are 1** (1 or 3 inputs high):
- Therefore, Sum is a **3-input XOR (odd parity) function**.

From canonical SOP:
$$
S_i = \sum m(1, 2, 4, 7) = \overline{A_i}\,\overline{B_i} C_i + \overline{A_i} B_i \overline{C_i} + A_i \overline{B_i}\,\overline{C_i} + A_i B_i C_i
$$
Factoring terms:
$$
\begin{aligned}
S_i &= \overline{A_i} (\overline{B_i} C_i + B_i \overline{C_i}) + A_i (\overline{B_i}\,\overline{C_i} + B_i C_i) \\
&= \overline{A_i} (B_i \oplus C_i) + A_i \overline{(B_i \oplus C_i)} \\
&= A_i \oplus (B_i \oplus C_i)
\end{aligned}
$$
$$
\mathbf{S_i = A_i \oplus B_i \oplus C_i}
$$
### 2.4 Canonical SOP Hardware vs. Optimized Hardware

A designer (or automated CAD tool) can realize the Full Adder in two distinct ways:

1. **Unoptimized Two-Level SOP Realization**:
   - Synthesizes all 8 minterms using eight 3-input AND gates.
   - Feeds $m_3, m_5, m_6, m_7$ into a 4-input OR gate for $C_{i+1}$.
   - Feeds $m_1, m_2, m_4, m_7$ into a 4-input OR gate for $S_i$.
   - *Advantage*: Entirely mechanical, easily automated without deductive reasoning.
   - *Disadvantage*: High transistor count and silicon area.
![](Pasted%20image%2020260924145956.png)
*Figure 2.1: Mechanical two-level SOP implementation of a 1-bit Full Adder using an 8-AND-gate minterm generator array feeding two OR gates (Source: Slide 66).*

2. **Optimized Modular Realization**:
   - Realized using an efficient 3-input XOR network for Sum and a 3-input Majority network for Carry-out.
![](Pasted%20image%2020260924150022.png)

# 3. Multi-Bit Adders & Architectural Trade-offs: Speed vs. Area

To perform arithmetic on multi-bit words (e.g., 4-bit, 32-bit, or 64-bit integers), multiple 1-bit adders must be coordinated.

### 3.1 The Ripple-Carry Adder (RCA)
The most straightforward method to add two $N$-bit numbers $A[N-1:0]$ and $B[N-1:0]$ is to cascade $N$ 1-bit full adders in series:
- For bit 0 (LSB): $C_0$ is tied to $0$ (or an external carry-in). Full Adder 0 computes $S_0$ and produces $C_1$.
- For bit 1: Full Adder 1 takes $A_1, B_1$, and $C_1$, computes $S_1$, and produces $C_2$.
- The carry bit **ripples sequentially** through the entire chain of adders from bit 0 to bit $N-1$.
![](Pasted%20image%2020260924150052.png)
*Figure 3.1: A 4-bit Ripple Carry Adder constructed by cascading four 1-bit Full Adders in series, showing the ripple carry chain (Source: Slide 34).*

#### Numerical Walkthrough: 4-Bit Binary Addition
Consider adding $A = 1011_2$ ($11_{10}$) and $B = 1001_2$ ($9_{10}$):
```
       Carries (C4..C1):   1  0  1  1  0 (C0)
       Operand A:             1  0  1  1
     + Operand B:             1  0  0  1
     ───────────────────────────────────
       Sum (S3..S0):          0  1  0  0   (with C4 = 1)
       Result: 10100_2 = 20_{10} (Correct)
```

#### The Critical Path and Latency Bottleneck
While operand inputs $A_i$ and $B_i$ are available simultaneously in parallel to all full adders, **the carry inputs are not**:
- Full Adder $i$ cannot evaluate its final, stable carry-out $C_{i+1}$ until Full Adder $i-1$ has settled and produced $C_i$.
- Therefore, the worst-case propagation delay scales linearly with word width:
	$$
	t_{\text{RCA}} = O(N) \approx N \times t_{\text{carry}}
	$$
- For a 64-bit adder in a modern 4 GHz CPU, waiting for 64 sequential gate stages would drastically lower clock frequency. Ripple carry adders are unviable for high-speed processor ALUs.

### 3.2 The Carry Lookahead Adder (CLA)
To overcome the serial bottleneck of the ripple carry adder, computer architects apply a fundamental design principle: **Decouple the generation of the carry from the serial sum computation**.
![](Pasted%20image%2020260924150140.png)
*Figure 3.2: Carry Lookahead Adder (CLA) architecture: (a) 32-bit hierarchical CLA composed of 4-bit CLA blocks, (b) Internal specialization logic calculating carries rapidly using Generate and Propagate logic (Source: Slide 36).*

#### Operational Concept
Instead of waiting for carry bits to propagate stage-by-stage:
1. Define two intermediate signals for each bit position:
   - **Generate ($G_i$)**: $G_i = A_i B_i$. The bit position generates a carry regardless of carry-in.
   - **Propagate ($P_i$)**: $P_i = A_i + B_i$ (or $A_i \oplus B_i$). The bit position propagates an incoming carry to the next stage.
2. Carry equations can be expanded directly in terms of the initial $C_{in}$ and inputs $A, B$:
	$$
	\begin{aligned}
	C_1 &= G_0 + P_0 C_{in} \\
	C_2 &= G_1 + P_1 C_1 = G_1 + P_1 G_0 + P_1 P_0 C_{in} \\
	C_3 &= G_2 + P_2 C_2 = G_2 + P_2 G_1 + P_2 P_1 G_0 + P_2 P_1 P_0 C_{in}
	\end{aligned}
	$$
3. Dedicated, specialized combinational logic evaluates these equations in parallel. The carries for an entire 4-bit group are produced in just 2 gate delays, bypassing the internal ripple chain.

#### The Fundamental Speed vs. Area Trade-off
> [!IMPORTANT]
> **Architectural Principle: Speed vs. Area / Hardware Cost**  
> To accelerate processing, identify the performance bottleneck (in adders: serial carry propagation) and build **specialized hardware** to bypass it.  
> Specialization improves latency ($O(\log N)$ instead of $O(N)$), but requires substantial extra silicon area for the lookahead logic gates. In modern computing, where transistors are plentiful, spending area to eliminate latency bottlenecks is a cornerstone architectural technique.

# 4. Programmable Logic Arrays (PLAs) & Functional Completeness

### 4.1 Programmable Logic Array (PLA) Architecture
A **Programmable Logic Array (PLA)** is a structured, regular combinational hardware block that implements arbitrary multi-input, multi-output Boolean functions directly in **two-level Sum of Products (SOP)** form.
![](Pasted%20image%2020260924150215.png)
*Figure 4.1: General structure of a Programmable Logic Array (PLA) comprising an input inverter stage, an AND array (minterm generation), a programmable interconnect matrix, and an OR array (output generation) (Source: Slide 39).*

#### Structural Components
1. **Inputs and Inverters**: Supplies both true ($A, B, C$) and complemented ($\overline{A}, \overline{B}, \overline{C}$) literals.
2. **AND Array (Product Plane)**: An array of AND gates that compute product terms (minterms or implicants). For an unconstrained $N$-input PLA, up to $2^N$ product lines exist.
3. **Programmable Interconnect Plane**: A grid of configurable connections (historically programmable fuses, antifuses, or MOS switches) routing selected product terms to OR gate inputs.
4. **OR Array (Sum Plane)**: An array of $M$ OR gates, where $M$ is the number of output columns required by the system specification.

### 4.2 Case Study: Implementing a Full Adder on a PLA
To implement a 1-bit Full Adder ($N=3$ inputs: $A_i, B_i, C_i$; $M=2$ outputs: $C_{i+1}, S_i$) on a PLA:
- The 3 inputs generate 8 minterm lines ($m_0$ through $m_7$).
- **Carry-out ($C_{i+1}$)**: Connects product lines $m_3, m_5, m_6, m_7$ to the $C_{i+1}$ OR gate.
- **Sum ($S_i$)**: Connects product lines $m_1, m_2, m_4, m_7$ to the $S_i$ OR gate.
- **Unused Hardware**: Product line $m_0$ is not connected to any output because no output is high for input pattern `000`. Any spare OR gates in the PLA matrix are left unconnected.
![](Pasted%20image%2020260924150319.png)
*Figure 4.2: Mapping the 1-bit Full Adder truth table onto a PLA matrix, showing connected minterm lines, the unused $m_0$ product line, and an unused spare OR gate (Source: Slide 41).*

> [!NOTE]
> **Evolution to FPGAs**: Early programmable devices relied heavily on PLAs and PALs (Programmable Array Logic). Modern FPGAs have replaced PLAs with SRAM-based Lookup Tables (LUTs), which provide superior density, routing flexibility, and dynamic reconfigurability.

### 4.3 Logical (Functional) Completeness
A set of logic gates is defined as **logically (functionally) complete** if any arbitrary Boolean function can be implemented using only gates from that set.

#### Completeness Theorems
1. **The Set $\{ \text{AND}, \text{OR}, \text{NOT} \}$ is Complete**:
   - *Proof*: Any arbitrary truth table can be converted into a canonical Sum of Products (SOP) expression. A canonical SOP expression contains only AND terms (products), OR terms (sums), and NOT operations (literal complements).
2. **The NAND Gate is Universally Complete on Its Own ($\{ \text{NAND} \}$)**:
   - **NOT from NAND**: Tie inputs together: $\overline{A} = A \text{ NAND } A$.
   - **AND from NAND**: Invert the NAND output: $A \cdot B = \text{NOT}(A \text{ NAND } B) = (A \text{ NAND } B) \text{ NAND } (A \text{ NAND } B)$.
   - **OR from NAND**: Apply De Morgan's Law ($\overline{\overline{A} \cdot \overline{B}} = A + B$): $A + B = (\overline{A}) \text{ NAND } (\overline{B}) = (A \text{ NAND } A) \text{ NAND } (B \text{ NAND } B)$.
3. **The NOR Gate is Universally Complete on Its Own ($\{ \text{NOR} \}$)**:
   - Symmetrically, NOT, OR, and AND can be synthesized exclusively from NOR gates using De Morgan's duality.

> [!TIP]
> **Architectural Significance**: Because CMOS technology naturally produces inverting gates (NAND and NOR), functional completeness proves that an entire microcomputer—including arithmetic processors, control units, and storage elements—can theoretically and practically be fabricated from a single universal gate type.

# 5. Advanced Combinational Building Blocks

Modern processor microarchitectures combine elementary gates into standardized, reusable macro-blocks.

### 5.1 The Comparator (Equality Checker)
A comparator evaluates whether two $N$-bit operands, $A[N-1:0]$ and $B[N-1:0]$, are bitwise identical.
![](Pasted%20image%2020260924150438.png)
*Figure 5.1: A 4-bit Equality Checker: logic symbol and gate schematic using bitwise XNOR gates feeding a 4-input AND gate (Source: Slide 50).*

#### Circuit Synthesis
- Two single bits $A_i$ and $B_i$ are identical if their **XNOR** output is 1:
	$$
	A_i \odot B_i = A_i B_i + \overline{A_i}\,\overline{B_i} = 1 \iff A_i = B_i
	$$
- For two $N$-bit words to be equal, **every bit pair must match simultaneously**:
	$$
	\text{Equal} = (A_{N-1} \odot B_{N-1}) \cdot (A_{N-2} \odot B_{N-2}) \cdots (A_0 \odot B_0)
	$$
- **Hardware Efficiency**: For a 4-bit comparator (8 inputs total), a brute-force PLA would require $2^8 = 256$ AND gates. In contrast, modular design requires only **4 XNOR gates and one 4-input AND gate**.
- **Real-World Application**: Comparators are ubiquitous in high-performance processors: matching associative cache tags, Translation Lookaside Buffer (TLB) virtual address lookup, and Out-of-Order (OoO) instruction wake-up logic in reservation stations.

### 5.2 The Arithmetic Logic Unit (ALU)
The **Arithmetic Logic Unit (ALU)** is the computational centerpiece of a CPU datapath. It integrates multiple arithmetic (addition, subtraction) and logical (AND, OR, comparison) operations into a single modular block.
![](Pasted%20image%2020260924150521.png)
*Figure 5.2: The standard ALU block symbol and an example function control table (Source: Slide 52).*

#### Function Control Specification (Harris & Harris Table 5.1)
An $N$-bit ALU takes two $N$-bit data inputs ($A, B$) and a 3-bit control input ($F_{2:0}$) specifying the active operation:

| Control Input $F_{2:0}$ | Function Performed | Operation Description |
| :---: | :---: | :--- |
| `000` | $A \text{ AND } B$ | Bitwise AND |
| `001` | $A \text{ OR } B$ | Bitwise OR |
| `010` | $A + B$ | Binary Addition |
| `011` | *Not used* | Reserved / Unused opcode |
| `100` | $A \text{ AND } \overline{B}$ | Bitwise AND with inverted $B$ |
| `101` | $A \text{ OR } \overline{B}$ | Bitwise OR with inverted $B$ |
| `110` | $A - B$ | Two's Complement Binary Subtraction |
| `111` | $\text{SLT}$ | Set Less Than: Output $Y = 1$ if $A < B$, else $Y = 0$ |

### 5.3 Concrete ALU Architecture Walkthrough
![](Pasted%20image%2020260924150537.png)
*Figure 5.3: Detailed hardware microarchitecture of an $N$-bit ALU showing operand inversion, adder sharing, SLT zero-extension, and output multiplexing (Source: Slide 53).*

#### Subsystem Breakdown
1. **Operand Inversion Multiplexer**:
   - Input $B$ passes directly to MUX input 0 and through an inverter bank to MUX input 1.
   - Controlled by the MSB of the function code, **$F_2$**:
	 $$
	 BB = \begin{cases} B & \text{if } F_2 = 0 \\ \overline{B} & \text{if } F_2 = 1 \end{cases}
	 $$
1. **Unified Adder / Subtractor**:
   - The adder takes operand $A$, operand $BB$, and carry-in $C_{in}$.
   - Crucially, the carry-in $C_{in}$ is wired directly to control line **$F_2$**!
     - When $F_2 = 0$: Adder computes $A + B + 0 = \mathbf{A + B}$.
     - When $F_2 = 1$: Adder computes $A + \overline{B} + 1$. By two's complement arithmetic, $\overline{B} + 1 = -B$. Therefore, the adder computes $\mathbf{A - B}$!
3. **Logic Operations (AND & OR)**:
   - Dedicated AND and OR gate arrays compute $A \cdot BB$ and $A + BB$ in parallel with the adder.
4. **Set Less Than (SLT) Logic**:
   - If $A < B$, then $A - B < 0$. In two's complement, negative numbers have a most significant bit (sign bit) of 1.
   - The sign bit $S[N-1]$ of the adder output is passed to a **Zero-Extension unit**, which zero-extends the 1-bit sign into an $N$-bit word ($00\dots01$).
5. **Output Selection Multiplexer**:
   - A 4-to-1 multiplexer controlled by **$F_{1:0}$** routes the selected result to output $Y$:
     - `00`: AND result ($A \cdot BB$)
     - `01`: OR result ($A + BB$)
     - `10`: Adder sum result ($A + BB + F_2$)
     - `11`: SLT zero-extended comparison result

> [!NOTE]
> **Why Unify Operations into an ALU?**  
> An architect could build separate, isolated functional units for addition, subtraction, AND, and OR. Unifying them into a standardized ALU enhances **modular abstraction**: the processor datapath interfaces with a single execution unit governed by a uniform control interface, amortizing hardware costs (e.g., sharing the multi-bit adder for both addition and subtraction).

### 5.4 Tri-State Buffers & Shared Communication Buses

In complex systems, multiple functional units (CPU, Memory, DMA Controller, GPU) must communicate across shared wires. Connecting two standard CMOS gate outputs directly together is illegal: if one gate drives $V_{DD}$ (1) and the other drives $GND$ (0), a low-resistance short circuit occurs, causing destructive current surges.

To solve this, hardware utilizes the **Tri-State Buffer**.
![](Pasted%20image%2020260924150557.png)
*Figure 5.4: Tri-State Buffer logic symbol and truth table showing high-impedance state ($Z$) (Source: Slide 57).*

#### Operational Principle
A tri-state buffer has a data input $A$, an enable input $E$, and an output $Y$:
- **$E = 1$ (Enabled)**: The buffer is active; $Y = A$ (drives 0 or 1 strongly).
- **$E = 0$ (Disabled)**: The buffer enters the **High-Impedance ($Z$) state**. The output is electrically disconnected from the wire (open circuit).

| Enable ($E$) | Input ($A$) | Output ($Y$) | Operational Mode |
| :---: | :---: | :---: | :--- |
| 0 | $X$ (Don't care) | **$Z$** | High-Impedance (Floating / Disconnected) |
| 1 | 0 | **0** | Active Low |
| 1 | 1 | **1** | Active High |

> [!CAUTION]
> **The Two Dangers of Tri-State Busses**:
> 1. **Bus Contention (Short Circuit)**: If two drivers are enabled simultaneously ($E_1 = 1, E_2 = 1$) driving opposing logic levels, massive current flows directly from $V_{DD}$ to $GND$, damaging the chip.
> 2. **Floating Bus ($Z$)**: If no driver is enabled ($E = 0$ for all drivers), the wire floats. Capacitive charge leakage and environmental electromagnetic noise will cause the voltage to wander, resulting in undefined read errors.

### 5.5 Shared Bus Architecture
Tri-state buffers enable bidirectional shared communication buses between major system modules:
![](Pasted%20image%2020260924150638.png)
*Figure 5.5: Shared system bus with CPU and Memory driving a common wire via mutually exclusive tri-state buffers (Source: Slide 59).*

- When the CPU writes to memory: $\text{Gate}_{\text{CPU}} = 1$, $\text{Gate}_{\text{Mem}} = 0$.
- When the Memory responds to CPU: $\text{Gate}_{\text{Mem}} = 1$, $\text{Gate}_{\text{CPU}} = 0$.
- Control logic guarantees that **at most one tri-state driver is active at any point in time**.

### 5.6 Multiplexers Implemented with Tri-State Buffers
Tri-state buffers offer an alternative, low-transistor-count method to construct multiplexers:
![](Pasted%20image%2020260924150648.png)
*Figure 5.6: Constructing 2-to-1 and 4-to-1 multiplexers using wired-OR tri-state buffer banks (Source: Slide 61).*

- **2-to-1 MUX**:
  - Buffer $T_0$ has an active-low enable ($\overline{S}$).
  - Buffer $T_1$ has an active-high enable ($S$).
  - Outputs are wired directly together to form $Y$:
    $$Y = D_0 \overline{S} + D_1 S$$
- **4-to-1 MUX**:
  - Four tri-state buffers whose enable inputs are driven by decoded select lines ($\overline{S_1}\,\overline{S_0}, \overline{S_1} S_0, S_1 \overline{S_0}, S_1 S_0$).

# 6. Systematic Logic Simplification & Minimization

A Boolean expression generated directly from a truth table is rarely optimal. The primary goal of logic minimization is to **reduce gate count, input literal count, delay, and power consumption**.

### 6.1 The Uniting Theorem (Boolean Adjacency)
Automated Electronic Design Automation (EDA) synthesis tools minimize logic by systematically applying **The Uniting Theorem**:
$$
\mathbf{A\overline{B} + AB = A(\overline{B} + B) = A \cdot 1 = A}
$$
#### Core Principle
If an input variable changes between two rows of the ON-set ($F = 1$) while all other input variables remain identical, **that variable has no impact on the function's output and can be eliminated**.

```
  Row 1 (ON-set):   A = 1, B = 0 ──► F = 1
  Row 2 (ON-set):   A = 1, B = 1 ──► F = 1
  Observation: B changes from 0 to 1, but F remains 1.
  Conclusion: Variable B is redundant. Output F = A.
```

The essence of logic simplification is discovering adjacent subsets of the truth table where only a single variable toggles.

### 6.2 Don't-Care ($X$) Conditions & Case Study: The Priority Circuit
In real systems, certain input combinations cannot occur physically or their output values are completely irrelevant to system correctness. These are designated as **Don't-Care ($X$) conditions**. Exploiting don't-cares dramatically compresses truth tables and simplifies circuits.

#### Case Study: 4-Bit Priority Arbiter
Consider 4 system modules ($A_3, A_2, A_1, A_0$) requesting access to a shared bus, with strict priority $A_3 > A_2 > A_1 > A_0$:
- Output $Y_i$ asserts 1 to grant the bus to requestor $A_i$.
![](Pasted%20image%2020260924150850.png)
*Figure 6.1: Full 16-row truth table for a 4-bit priority arbiter highlighting the static priority hierarchy (Source: Slide 71).*

#### Compressed Truth Table with Don't-Cares
If $A_3$ asserts a request, it receives the grant ($Y_3 = 1$) regardless of whether lower-priority requestors ($A_2, A_1, A_0$) are requesting. Their values do not matter ($X$):

| $A_3$ | $A_2$ | $A_1$ | $A_0$ | $Y_3$ | $Y_2$ | $Y_1$ | $Y_0$ | Active Grant |
| :---: | :---: | :---: | :---: | :---: | :---: | :---: | :---: | :--- |
| 0 | 0 | 0 | 0 | **0** | **0** | **0** | **0** | None (Idle) |
| 0 | 0 | 0 | 1 | **0** | **0** | **0** | **1** | Requestor 0 Granted |
| 0 | 0 | 1 | $X$ | **0** | **0** | **1** | **0** | Requestor 1 Granted |
| 0 | 1 | $X$ | $X$ | **0** | **1** | **0** | **0** | Requestor 2 Granted |
| 1 | $X$ | $X$ | $X$ | **1** | **0** | **0** | **0** | Requestor 3 Granted |
![](Pasted%20image%2020260924150911.png)
*Figure 6.2: Compressed priority circuit truth table using Don't-Care ($X$) conditions and the resulting minimal gate schematic (Source: Slide 72).*

#### Synthesized Minimal Equations
Reading directly from the simplified table:
$$
\begin{aligned}
Y_3 &= A_3 \\
Y_2 &= \overline{A_3} A_2 \\
Y_1 &= \overline{A_3}\,\overline{A_2} A_1 \\
Y_0 &= \overline{A_3}\,\overline{A_2}\,\overline{A_1} A_0
\end{aligned}
$$
Hardware synthesis requires merely four gates with inversion bubbles, saving dozens of transistors compared to naive two-level SOP logic.

### 6.3 Karnaugh Maps (K-Maps)
A **Karnaugh Map (K-Map)** is a visual, graphical representation of a truth table arranged in a multidimensional grid using **Gray code ordering** (where adjacent cells differ by exactly one bit).
- Grouping adjacent cells of 1s in powers of two ($2, 4, 8, \dots$) mechanically executes the Uniting Theorem visually.
- *(Note: K-Maps are an invaluable tool for manual design; modern EDA synthesis algorithms utilize tabular algebraic algorithms such as Quine-McCluskey and Espresso).*

# 7. The Transition to Sequential Logic: Memory as a Necessity

### 7.1 The Fundamental Limitation of Combinational Circuits
Every circuit examined so far has been **combinational**:
- The outputs depend **strictly on the current inputs**:
	$$
	Y(t) = f(X(t))
	$$
- A combinational circuit has **no memory of past inputs or historical events**.

However, meaningful computation requires state:
- An accumulator adding a stream of numbers must remember the running total.
- A central processing unit must remember where it is in a program (Program Counter).
- A lock must remember the sequence of digits entered.

#### The Lock Analogy
- **Combinational Lock**: A 4-dial luggage padlock opens strictly based on the present position of the dials. It does not care how the dials arrived at that position.
- **Sequential Lock**: A rotary safe combination lock requires a precise sequence of past actions (e.g., rotate right to 13, left to 22, right to 3). The lock opens only if past inputs occurred in the correct sequence.
![](Pasted%20image%2020260924151001.png)
*Figure 7.1: Conceptual distinction: Combinational lock (depends strictly on current inputs) vs. Sequential lock (depends on current and past history) (Source: Slide 128).*

### 7.2 Canonical Model of a Sequential Circuit
A **sequential logic circuit** combines a combinational logic network with **storage (memory) elements** connected in a feedback loop:
![](Pasted%20image%2020260924151022.png)
*Figure 7.2: Canonical structure of a sequential circuit: combinational logic paired with storage elements in a feedback loop (Source: Slide 91).*

- The **Storage Elements** preserve the current **State** of the system.
- The **Combinational Logic** evaluates the system's outputs and determines the **Next State** based on both the current inputs and the stored current state.

### 7.3 The Dominance of Memory in Modern Systems
Memory is not an incidental peripheral; it physically dominates modern computing hardware.
- On modern microprocessor chips, **over 50% to 80% of the entire silicon die area is dedicated exclusively to memory** (SRAM caches, register files, scratchpads).
![](Pasted%20image%2020260924151046.png)
*Figure 7.3: High-resolution die shot of the AMD Ryzen 5000 (Zen 3) processor: the vast central area is completely dominated by SRAM L3 and L2 cache memory arrays (Source: Slide 85).*

From the 1995 Intel Pentium Pro multi-chip module cache to modern 3D stacked chips (such as AMD 3D V-Cache stacking 64 MB SRAM dies using Through-Silicon Vias) and the Cerebras Wafer-Scale Engine-3, computing systems are predominantly storage arrays orchestrated by processing logic.

### 7.4 The Memory Technology Spectrum
Different storage technologies navigate strict trade-offs between access speed, silicon area, manufacturing complexity, and cost:

| Memory Technology | Relative Latency | Cost / Area per Bit | Volatility | Circuit Composition | Primary Role in Computers |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Latches & Flip-Flops** | Picoseconds (Fastest) | Very Expensive (10–20+ transistors) | Volatile | Cross-coupled logic gates | Processor registers, pipeline state |
| **Static RAM (SRAM)** | 1–3 Nanoseconds | Expensive (6 transistors: 6T cell) | Volatile | Cross-coupled inverters + access FETs | L1, L2, L3 on-chip processor caches |
| **Dynamic RAM (DRAM)** | Tens of Nanoseconds | Cheap (1 transistor + 1 capacitor: 1T1C) | Volatile (requires periodic refresh) | Specialized capacitor storage trench | Off-chip main system memory |
| **Flash / Solid-State (SSD)** | Microseconds | Very Cheap | **Non-Volatile** (retains data without power) | Floating-gate / 3D Charge-trap transistors | Secondary persistent storage |
| **Magnetic Hard Disk (HDD)** | Milliseconds | Extremely Cheap | **Non-Volatile** | Magnetic platter domains | Mass archival data storage |

# 8. Circuits That Store Information: From Inverters to Registers

How do we capture and store a single bit of information using electrical switches?

### 8.1 The Primitive Storage Element: Cross-Coupled Inverters
The absolute simplest circuit exhibiting memory is formed by connecting two CMOS inverters head-to-tail in a positive feedback loop:
![](Pasted%20image%2020260924151122.png)
*Figure 8.1: Cross-coupled inverters forming a bi-stable storage element: (a) Stable State 0 ($Q=0, \overline{Q}=1$), (b) Stable State 1 ($Q=1, \overline{Q}=0$) (Source: Slide 93).*

#### Operating States
- **Stable State 0**: If $Q = 0$, Inverter 2 inverts it to $\overline{Q} = 1$. Inverter 1 inverts $\overline{Q} = 1$ back to $Q = 0$. The state is perpetually reinforced.
- **Stable State 1**: If $Q = 1$, Inverter 2 inverts it to $\overline{Q} = 0$. Inverter 1 inverts $\overline{Q} = 0$ back to $Q = 1$.
- **Metastable State**: If both nodes hover near the switching threshold ($V_{DD} / 2$), the circuit enters an unstable equilibrium. Any minute thermal or electrical noise will cause the circuit to rapidly fall into either State 0 or State 1.

#### The Fatal Flaw
While cross-coupled inverters successfully preserve a bit, **the circuit is practically useless on its own because there are no input terminals to write or update $Q$**.

### 8.2 Peek into Static RAM (SRAM 6T Cell)
To convert cross-coupled inverters into a writable memory cell, Static RAM (SRAM) augments the loop with two NMOS access transistors controlled by a `wordline`:
![](Pasted%20image%2020260924151156.png)
*Figure 8.2: A 6-Transistor (6T) SRAM cell: cross-coupled inverters with access transistors connected to differential bitlines (Source: Slide 94).*

- Asserting the `wordline` connects the internal storage nodes to differential vertical wires (`bitline` and $\overline{\text{bitline}}$), enabling high-speed read and write operations.

### 8.3 The R-S (Reset-Set) Latch
To provide digital logic control over the cross-coupled loop, we replace the inverters with **2-input NAND gates**:
![](Pasted%20image%2020260924151217.png)
*Figure 8.3: The R-S Latch constructed with cross-coupled NAND gates and its operational truth table (Source: Slide 97).*

#### Terminals & Operation
The latch has two control inputs: **$S$ (Set)** and **$R$ (Reset)**, and complementary outputs $Q$ and $Q'$ ($\overline{Q}$).
*(Note: In a cross-coupled NAND latch, the control inputs are active-low).*

1. **Quiescent / Hold State ($R = 1, S = 1$)**:
   - Both NAND gates act as standard inverters for their cross-coupled inputs.
   - The circuit retains its stored value: $Q_{\text{next}} = Q_{\text{prev}}$.
2. **Set State ($S = 0, R = 1$)**:
   - Because any 0 into a NAND forces the output to 1: $S = 0 \implies Q = 1$.
   - $Q = 1$ and $R = 1$ feed the bottom NAND, forcing $Q' = 0$.
   - The latch stores a **1**.
3. **Reset State ($S = 1, R = 0$)**:
   - $R = 0$ forces the bottom NAND output $Q' = 1$.
   - $Q' = 1$ and $S = 1$ feed the top NAND, forcing $Q = 0$.
   - The latch stores a **0**.

#### Truth Table: NAND R-S Latch
| Reset ($R$) | Set ($S$) | Next State ($Q$)  | State Description                                                     |
| :---------: | :-------: | :---------------: | :-------------------------------------------------------------------- |
|      1      |     1     | $Q_{\text{prev}}$ | **Hold (Quiescent)** — Retains stored bit                             |
|      1      |     0     |         1         | **Set** — Writes 1 to $Q$                                             |
|      0      |     1     |         0         | **Reset** — Writes 0 to $Q$                                           |
|      0      |     0     |   **Forbidden**   | **Illegal State** — Violates complementarity & triggers metastability |

### 8.4 Why Is $R = S = 0$ Forbidden?
Driving both $R = 0$ and $S = 0$ simultaneously is strictly forbidden in digital design for two fundamental reasons:

1. **Violation of the Invariant Principle**:
   - If $R = 0$ and $S = 0$, both NAND gates are forced to output 1 simultaneously ($Q = 1$ and $Q' = 1$).
   - This directly breaks the logical invariant that $Q$ and $Q'$ must be logical complements ($Q = \overline{Q'}$).
2. **Metastability and Non-Deterministic Race Conditions**:
   - If both inputs transition from $0 \to 1$ simultaneously (returning to Hold mode), both NAND gates simultaneously see inputs of `11` and attempt to pull their outputs to 0.
   - The outputs enter an analog race condition, oscillating or hovering in a **metastable state**.
   - Which state (0 or 1) the latch eventually settles into depends entirely on microscopic semiconductor variations, wire capacitances, and thermal noise. The circuit effectively behaves as a random noise generator rather than a deterministic memory cell.

### 8.5 The Gated D Latch
Relying on external circuit designers to avoid the forbidden state ($R=S=0$) is unsafe. To make storage robust, we construct the **Gated D Latch**.
![](Pasted%20image%2020260924151249.png)
*Figure 8.4: Schematic of a Gated D Latch using four NAND gates and an inverter, eliminating the forbidden state and providing a Write Enable control interface (Source: Slide 102).*

#### Architectural Improvement
The Gated D Latch encapsulates the cross-coupled NAND core with two input gating NAND gates and an inverter:
- It exposes a single data input **$D$** and a **Write Enable ($WE$)** control line.
- The internal signals $S$ and $R$ are derived automatically:
$$
S = \overline{D \cdot WE}, \quad R = \overline{\overline{D} \cdot WE}
$$
#### Operational Modes
- **When $WE = 0$ (Hold Mode)**:
  - Both gating NAND outputs are forced to 1 ($S = 1, R = 1$).
  - The internal latch is in Quiescent mode: input $D$ is completely ignored, and $Q$ maintains its previous value ($Q = Q_{\text{prev}}$).
- **When $WE = 1$ (Transparent / Write Mode)**:
  - If $D = 1 \implies S = 0, R = 1 \implies Q = 1$.
  - If $D = 0 \implies S = 1, R = 0 \implies Q = 0$.
  - Output $Q$ tracks data input $D$.
- **Guaranteed Invariant Safety**: Because $D$ and $\overline{D}$ are complementary, $S$ and $R$ **can never be 0 at the same time**. The forbidden state is physically impossible to trigger!

#### Truth Table: Gated D Latch
| Write Enable ($WE$) | Data Input ($D$) | Next Output ($Q$) | Functional Description |
| :---: | :---: | :---: | :--- |
| 0 | $X$ (Don't care) | $Q_{\text{prev}}$ | **Memory Mode** — Latched, state unchanged |
| 1 | 0 | 0 | **Write Mode** — Writes 0 |
| 1 | 1 | 1 | **Write Mode** — Writes 1 |

### 8.6 The Multi-Bit Register
To store multi-bit data words (e.g., 4-bit, 32-bit, or 64-bit values), multiple Gated D Latches are placed in parallel:
- All latches share a single, common **Write Enable ($WE$)** control wire.
- When $WE = 1$, all bits of input vector $D[N-1:0]$ are loaded simultaneously into the latches.
- When $WE = 0$, all latches hold their stored data on output vector $Q[N-1:0]$.
![](Pasted%20image%2020260924151314.png)
*Figure 8.5: Internal organization of a 4-bit Register constructed from four parallel Gated D Latches sharing a common Write Enable line (Source: Slide 104).*

# 9. Building Modular Memory Arrays from Storage Elements

A single register stores one data word. A **Memory Array** scales this concept to organize thousands, millions, or billions of registers into an addressable, structured matrix.

### 9.1 Fundamental Memory Metrics
1. **Address Space**: The total number of uniquely addressable storage locations ($2^k$ locations indexed by $k$ address bits).
2. **Addressability**: The number of data bits stored inside each individual location ($M$ bits per word).
3. **Total Memory Capacity**: $\text{Capacity} = 2^k \times M$ bits.

### 9.2 Architecture of a 2-Location $\times$ 3-Bit Memory Array
To understand memory architecture, consider a 6-bit memory array organized as **2 locations with 3-bit addressability**:
- Requires $k = \log_2(2) = 1$ address bit ($Addr[0]$).
- Each location contains a 3-bit register (three Gated D Latches).
![](Pasted%20image%2020260924151407.png)
*Figure 9.1: Complete schematic of a 2-location by 3-bit memory array implementing both read and write functionality (Source: Slide 116).*

#### 1. Writing Mechanism
- The address line $Addr[0]$ passes to a **1-to-2 Address Decoder** (an inverter).
  - Row 0 decode line: $\overline{Addr[0]}$
  - Row 1 decode line: $Addr[0]$
- Each decoded row line is ANDed with the global **Write Enable ($WE$)** signal to drive the latch write enables of that specific row:
  - Row 0 Write Enable $= WE \cdot \overline{Addr[0]}$
  - Row 1 Write Enable $= WE \cdot Addr[0]$
- Data input lines $D_i[2:0]$ are routed vertically to all rows. When $WE = 1$, only the addressed row latches the data.

#### 2. Reading Mechanism
- Reading is achieved using **Multiplexers** controlled by the address decoder:
  - Each bit column has a 2-to-1 MUX formed by two AND gates feeding an OR gate.
  - The read AND gates of Row 0 are enabled by $\overline{Addr[0]}$.
  - The read AND gates of Row 1 are enabled by $Addr[0]$.
  - The OR gates combine the signals to produce output data $D[2:0]$.

### 9.3 Scaling Up: A 4-Location $\times$ 3-Bit Memory Array
Scaling the memory to 4 locations ($2^2 \times 3$ bits = 12 bits total) demonstrates the modular hierarchy of large memories:
![](Pasted%20image%2020260924151430.png)
*Figure 9.2: A 4-location by 3-bit memory array showing the 2-to-4 Address Decoder (green) and three 4-to-1 Column Read Multiplexers (brown) (Source: Slide 118).*

#### Structural Subsystems
- **Address Decoder (2-to-4 Decoder)**: Converts a 2-bit address $Addr[1:0]$ into 4 mutually exclusive horizontal **Wordlines**. Exactly one wordline is asserted high at any time.
- **Bitlines / Data Buses**: Vertical wires supplying input data $D_i[2:0]$ during writes, and gathering output data $D[2:0]$ during reads.
- **Column Multiplexers**: Three 4-to-1 multiplexers (one per column) route the active row's bits to the outputs.

### 9.4 Step-by-Step Execution: Reading Location 3
![](Pasted%20image%2020260924151456.png)
*Figure 9.3: Step-by-step signal propagation when reading Location 3 ($Addr = 11_2, WE = 0$) from a 4x3-bit memory array (Source: Slide 119).*

1. **Apply Address & Controls**:
   - Address inputs set to $Addr[1:0] = 11_2$ (Location 3).
   - Write Enable set to $WE = 0$ (Disable writing).
2. **Decode Phase**:
   - The 2-to-4 address decoder asserts Wordline 3 high (`1`) while Wordlines 0, 1, and 2 remain low (`0`).
1. **Write Isolation**:
   - Because $WE = 0$, all write-gating AND gates output 0. No latches are overwritten.
4. **Read Multiplexing**:
   - Wordline 3 activates the read AND gates for Row 3.
   - All read AND gates for Rows 0, 1, and 2 are disabled (outputting 0).
   - The stored bits of Location 3 (in this example, `101`) pass through the enabled AND gates and traverse the column OR gates.
5. **Output**:
   - The memory array reliably outputs $D[2:0] = 101_2$.

### 9.5 Memory Arrays as Universal Lookup Tables (LUTs)
Just as multiplexers can implement logic, **memory arrays can implement any arbitrary combinational logic function**:
- An $N$-input, $M$-output Boolean function can be implemented by storing its complete truth table inside a **$2^N$-location $\times$ $M$-bit memory array**.
- Function inputs are wired directly to the **Address lines**.
- The pre-programmed data stored at that address appears at the **Data outputs**.
- For example, a 2-input AND gate can be implemented on a 4-location $\times$ 1-bit memory by storing bits `[0, 0, 0, 1]` at addresses `00, 01, 10, 11`.
- **FPGA Realization**: This principle is the exact mechanism by which FPGAs configure arbitrary combinational and sequential logic dynamically.

## 10. Summary & Key Takeaways

1. **Arithmetic Circuits**:
   - The 1-bit Full Adder adds two operand bits and a carry-in, computing Sum via a **3-input XOR** ($S_i = A_i \oplus B_i \oplus C_i$) and Carry-out via a **3-input Majority function** ($C_{i+1} = A_i B_i + A_i C_i + B_i C_i$).
   - Ripple Carry Adders (RCAs) chain full adders sequentially, causing an $O(N)$ carry propagation delay bottleneck.
   - Carry Lookahead Adders (CLAs) trade increased silicon area for speed, calculating carries in parallel using Generate ($G_i$) and Propagate ($P_i$) logic.
1. **Structured & Reconfigurable Logic**:
   - Programmable Logic Arrays (PLAs) implement two-level SOP logic using a programmable AND plane followed by a programmable OR plane.
   - The gate sets $\{ \text{AND}, \text{OR}, \text{NOT} \}$, $\{ \text{NAND} \}$, and $\{ \text{NOR} \}$ are each **functionally complete**; entire computers can be constructed exclusively from NAND gates.
3. **Advanced Combinational Units**:
   - Comparators test equality using bitwise XNOR gates feeding an AND gate, widely used in cache tag matching and out-of-order execution logic.
   - The Arithmetic Logic Unit (ALU) combines arithmetic and bitwise logic into a single modular block, leveraging two's complement inversion to perform both addition and subtraction on a shared adder.
   - Tri-State Buffers provide a high-impedance ($Z$) disconnected state, allowing multiple drivers to share physical communication buses without destructive short circuits.
4. **Systematic Logic Minimization**:
   - Modern EDA synthesis algorithms apply the **Uniting Theorem** ($A\overline{B} + AB = A$) to eliminate redundant input variables.
   - Don't-Care ($X$) conditions allow dramatic truth table and gate minimization in circuits like Priority Arbiters.
5. **Foundations of Memory & Storage**:
   - Memory physically dominates modern processors, occupying over 50–80% of silicon die area.
   - Storage technologies navigate strict trade-offs: Latches/Flip-Flops (fastest, most expensive), SRAM (fast 6T on-chip caches), DRAM (dense 1T1C off-chip main memory), and Flash (dense, non-volatile).
   - The **Gated D Latch** resolves the forbidden state ($R=S=0$) and metastability hazards of the cross-coupled NAND R-S latch by encapsulating control via a Write Enable ($WE$) signal.
   - Multi-bit registers group Gated D Latches under a shared $WE$ line.
   - Addressable Memory Arrays combine registers into a 2D matrix using **Address Decoders** for wordline selection and **Multiplexers** for column data reading.
