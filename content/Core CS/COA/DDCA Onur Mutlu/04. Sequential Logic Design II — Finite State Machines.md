# 2. Recap: Storage Elements & Memory Hierarchy

Before advancing to edge-triggered elements, we review the storage hierarchy developed in lecture 3:

```
[ Cross-Coupled Inverter ] ──► [ R-S Latch ] ──► [ Gated D Latch ] ──► [ Master-Slave D Flip-Flop ]
       (Read-only)             (Forbidden State)   (Transparent)             (Edge-Triggered)
```

### 2.1 The Storage Spectrum

1. **Cross-Coupled Inverters**: The simplest bistable element utilizing positive feedback (4 transistors). It reliably stores one bit in either State 0 or State 1, but possesses **no input mechanism** to write new data.
2. **R-S (Reset-Set) Latch**: Augments cross-coupled feedback with control inputs (NOR or NAND implementations). Provides explicit Set ($S$) and Reset ($R$) controls. **Fatal flaw**: The forbidden input condition ($S=R=0$ for active-low NAND latches; $S=R=1$ for active-high NOR latches) forces complementary outputs to identical values ($Q = \overline{Q} = 1$) and induces unpredictable oscillation or **metastability** upon deassertion.
3. **Gated D Latch**: Solves the forbidden state by deriving $S$ and $R$ from a single data input $D$ and its complement $\overline{D}$, gated by a **Write Enable** ($WE$) signal (~20 transistors).
![](Pasted%20image%2020260925215609.png)
*Figure 2.1: The Gated D Latch schematic and operational truth table. When $WE = 0$, outputs retain their previous stored state $Q_{\text{prev}}$. When $WE = 1$, the latch is transparent and $Q$ follows $D$ (Source: Slide 7).*

| $WE$ | $D$ | $Q$ | $\overline{Q}$ | Operational Mode |
| :---: | :---: | :---: | :---: | :--- |
| 0 | $X$ | $Q_{\text{prev}}$ | $\overline{Q_{\text{prev}}}$ | **Hold / Memory** (latch closed) |
| 1 | 0 | 0 | 1 | **Reset** ($Q$ follows $D$) |
| 1 | 1 | 1 | 0 | **Set** ($Q$ follows $D$) |

4. **Multi-Bit Registers**: Parallel banks of storage cells sharing a common Write Enable line, allowing synchronous capture of $N$-bit data words.
5. **Two-Dimensional Memory Arrays**: Grids of storage cells integrated with an $N$-to-$2^N$ **Address Decoder** (asserting horizontal Wordlines) and vertical **Bitlines** multiplexed to data outputs, enabling compact storage scaling ($2^k \times M$ bits).
![](Pasted%20image%2020260925215646.png)
*Figure 2.2: A $4 \times 3$-bit Memory Array composed of Gated D Latches. An Address Decoder decodes $\text{Addr}[1:0]$ to selectively assert a single wordline. An output multiplexer selects the corresponding 3-bit word onto $D[2:0]$ (Source: Slide 8).*

# 3. The Concept of State

### 3.1 Combinational vs. Sequential Operations

Digital systems are fundamentally partitioned into two categories:

- **Combinational Systems**: Strictly **memoryless**. The output at time $t$ depends purely on the inputs applied at time $t$:  
	$$
	Y(t) = f(X(t))
	$$
	*Analogy: A combination padlock*. The lock opens if and only if the dials currently display the correct digits, regardless of previous attempts.

- **Sequential Systems**: Possess **memory**. The output at time $t$ depends on current inputs as well as the historical sequence of past inputs:  
	$$
	Y(t) = f(X(t), \text{History}(t))
	$$
	*Analogy: A dial safe combination lock*. The lock requires dialing Right to 13 ($R13$), then Left to 22 ($L22$), then Right to 3 ($R3$). Dialing the numbers out of order or inserting extraneous turns leaves the safe locked.

### 3.2 Formal Definition of State

> [!IMPORTANT]
> **The state of a system is a snapshot of all relevant elements of the system at the moment of the snapshot.**

The state completely encapsulates the past history necessary to determine future system behavior. Once the current state is known, past inputs can be discarded.

#### Case Study: The Sequential Dial Lock
Consider a sequential lock requiring the passcode sequence **R13 $\to$ L22 $\to$ R3**:

- **State A**: Locked. Initial rest state; no valid sequence started.
- **State B**: Locked. User successfully completed **R13**. Awaiting $L22$.
- **State C**: Locked. User successfully completed **R13 $\to$ L22**. Awaiting $R3$.
- **State D**: **Unlocked**. User successfully completed **R13 $\to$ L22 $\to$ R3**.

Any deviation from the required sequence (e.g., dialing $L5$ while in State B) aborts the sequence and immediately resets the system to **State A**.
![](Pasted%20image%2020260925215850.png)
*Figure 3.1: State diagram of the sequential combination lock. Circles represent states; directed arcs represent transitions triggered by user dial inputs. Erroneous inputs force a return to State A (Source: Slide 13, Patt and Patel, 2nd ed., page 76).*

# 4. Synchronous vs. Asynchronous Systems & The Clock Discipline

### 4.1 Comparison of Paradigms

| Characteristic | Asynchronous Systems | Synchronous Systems |
| :--- | :--- | :--- |
| **Transition Trigger** | Immediate upon input changes | Strictly at discrete, periodic points in time |
| **Coordination** | Local handshaking / delay matching | Central periodic **Clock ($CLK$)** signal |
| **Design Complexity** | High; vulnerable to races, hazards, and skew | Modular; decoupled by clock periods |
| **Performance Overhead** | No clock overhead; potentially faster | Governed by worst-case critical path delay |
| **System Dominance** | Specialized low-power or interface circuits | **Standard for nearly all modern computers** |

### 4.2 The Clock Signal

The **Clock ($CLK$)** is an oscillator signal alternating between logic `0` and logic `1` at a constant frequency $f = 1/T_c$:

```
        ◄──────── Clock Period (Tc) ────────►
        ┌──────────────┐                     ┌──────────────┐
CLK:  ──┘  (Clock High) └─────────────────────┘  (Clock High) └──────
        ▲                                    ▲
   Rising Edge                          Rising Edge
 (State Transition)                   (State Transition)
```

- **Rising Edge (Positive Edge)**: The $0 \to 1$ voltage transition that serves as the universal synchronization strobe across all sequential elements in the chip.
- **Clock Period ($T_c$)**: The time between successive rising edges.
- **Cycle Invariance**: The state remains completely **stable and unchanged** throughout the clock period, allowing combinational logic the full duration to compute next-state values.

#### Swiss Traffic Light Model
A standard Swiss traffic light illustrates a simple cyclic autonomous state machine:

$$
\text{State A (Green)} \longrightarrow \text{State B (Yellow)} \longrightarrow \text{State C (Red)} \longrightarrow \text{State D (Red + Yellow)} \longrightarrow \text{State A}
$$

Each state persists for an integer number of clock ticks, driven predictably by the clock.

### 4.3 The Fundamental Synchronous Timing Constraint

> [!IMPORTANT]
> The clock cycle period $T_c$ must be strictly greater than or equal to the maximum combinational propagation delay ($t_{pd}$) through the longest path (the **critical path**), plus setup and propagation delays of the state elements:
> $$
> T_c \ge t_{pd, \text{reg}} + t_{pd, \text{comb}} + t_{\text{setup}}
> $$
> If the clock frequency is increased beyond this limit, next-state values will fail to settle before the next clock edge, corrupting the stored state.

# 5. Synchronous Sequential Circuit Structures

Synchronous circuits combine combinational logic with clocked state storage elements in closed feedback loops:
![](Pasted%20image%2020260925215939.png)
*Figure 5.1: Canonical structures of digital systems. Top: Purely combinational circuit (no state). Middle-left: Simple sequential circuit with feedback through a state register. Middle-right: Multi-block sequential circuit. Bottom: Pipelined architecture where combinational stages alternate with clocked registers (Source: Slide 20, H&H Fig 3.2.1).*

### 5.1 Pipelining Foundations
As illustrated in Figure 5.1 (bottom), dividing long combinational logic into stages separated by registers forms a **pipeline**:
$$
\text{Register} \longrightarrow \text{Combinational Logic 1} \longrightarrow \text{Register} \longrightarrow \text{Combinational Logic 2} \longrightarrow \text{Register}
$$
- Each sub-stage evaluates in parallel on different consecutive data tokens.
- Latency per operation increases slightly due to register delays, but **system throughput** increases dramatically because $T_c$ is determined only by the slowest individual sub-stage rather than the entire pipeline.

# 6. The Problem with Latches: Transparency

### 6.1 Why Latches Cannot Implement State Registers

Attempting to implement a state register by wiring $CLK$ directly to the Write Enable ($WE$) of a Gated D Latch causes severe design failures:
![](Pasted%20image%2020260925220022.png)
*Figure 6.1: The transparency hazard. While $CLK = 1$, the Gated D Latch is transparent ($Q$ continuously tracks $D$). Input glitches or race conditions propagate through feedback logic multiple times during a single clock pulse, corrupting the intended state (Source: Slide 28).*

- **Level-Sensitive Transparency**: Whenever $CLK = 1$, the latch behaves as a simple transparent wire between $D$ and $Q$.
- **Feedback Oscillation (Race-Around Condition)**: In a closed feedback loop:  
$$
Q \longrightarrow [\text{Next State Logic}] \longrightarrow D \longrightarrow Q
$$
  If $t_{pd, \text{comb}} < T_{\text{high}}$, the updated output $Q$ ripples through the combinational logic and changes $D$ *while the clock is still high*. This produces a continuous, uncontrollable sequence of state transitions during a single clock cycle.

### 6.2 State Register Requirements

To build deterministic sequential circuits, storage elements must guarantee:
1. **Edge Sampling**: Sample input $D$ precisely at the clock transition ($0 \to 1$).
2. **Cycle Isolation**: Hold output $Q$ completely stable for the remainder of the clock period, regardless of any changes or glitches on input $D$.

# 7. The D Flip-Flop (Master-Slave Architecture)

### 7.1 Master-Slave Construction

The **Master-Slave D Flip-Flop** solves the transparency problem by cascading **two Gated D Latches** controlled by **complementary clock signals**:
![](Pasted%20image%2020260925220045.png)
*Figure 7.1: Master-Slave D Flip-Flop circuit schematic. When $CLK=0$, the Master latch is enabled ($\overline{CLK}=1$) and tracks $D$, while the Slave latch holds previous state $Q$. When $CLK$ transitions from $0 \to 1$, the Master disconnects from $D$, and the Slave captures the Master's output, transferring it to $Q$ (Source: Slide 32).*

#### Detailed Operational Walkthrough

1. **Phase 1: Clock Low ($CLK = 0$, $\overline{CLK} = 1$)**:
   - **Master Latch**: Transparent ($WE = 1$). The internal node tracks input $D$.
   - **Slave Latch**: Opaque / Hold mode ($WE = 0$). Output $Q$ remains clamped to its previous value.
   - *Result*: Changes to input $D$ propagate only to the midpoint node; output $Q$ is completely isolated from $D$.

2. **Phase 2: Rising Clock Edge ($CLK: 0 \to 1$)**:
   - **Master Latch**: Closes instantly ($WE: 1 \to 0$), locking in whatever value $D$ had just before the clock edge.
   - **Slave Latch**: Opens instantly ($WE: 0 \to 1$), reading the locked value from the Master and presenting it at $Q$.
   - *Result*: The value of $D$ at the instant of the rising edge is transferred to $Q$.

3. **Phase 3: Clock High ($CLK = 1$, $\overline{CLK} = 0$)**:
   - **Master Latch**: Stays closed ($WE = 0$). Any subsequent changes, noise, or logic transitions on $D$ are completely blocked.
   - **Slave Latch**: Stays transparent ($WE = 1$), continuing to drive the captured value onto $Q$.
   - *Result*: $Q$ remains perfectly constant for the entire high phase.

> [!TIP]
> The Master-Slave topology guarantees that at no point in time is there an open transparent path between input $D$ and output $Q$. One latch is always closed when the other is open.

### 7.2 Schematic Symbol & Classification
![](Pasted%20image%2020260925220100.png)
*Figure 7.2: Standard schematic symbol for the rising-edge-triggered D Flip-Flop. The small triangle on the clock terminal denotes edge-triggered operation (Source: Slide 33).*

- **Latch**: A **level-triggered** storage element (transparent during the active clock level).
- **Flip-Flop**: An **edge-triggered** storage element (samples exclusively at the active clock transition).
- **Cost**: A D Flip-Flop requires two complete latches plus clock inverter logic ($\approx 40\text{--}46$ transistors), roughly double the hardware area of a single latch.

### 7.3 Multi-Bit D-Flip-Flop Registers

Multiple D Flip-Flops driven by a shared clock line form multi-bit registers:

*Figure 7.3: A 4-bit synchronous register constructed from four parallel D Flip-Flops sharing a single $CLK$ net. Right: Standard bus notation showing bit-width slash (Source: Slide 36).*
![](Pasted%20image%2020260925220127.png)

# 8. Finite State Machines (FSMs)

### 8.1 Formal Definition

A **Finite State Machine (FSM)** is a discrete-time computational model consisting of:
1. A **finite set of states** ($S$).
2. A **finite set of external inputs** ($I$).
3. A **finite set of external outputs** ($O$).
4. A **state transition function** (Next State Logic) mapping $(S(t), I(t)) \to S(t+1)$.
5. An **output function** (Output Logic) mapping states (and inputs) to external outputs.

### 8.2 Canonical FSM Hardware Architecture

An FSM is partitioned into three distinct hardware subsystems:

![FSM Architecture](page-24.png)
*Figure 8.1: Canonical hardware decomposition of a Finite State Machine: combinational Next State Logic, clocked State Register, and combinational Output Logic (Source: Slide 24).*

1. **State Register**: $k$ flip-flops storing the binary representation of the current state ($2^k \ge |S|$). Updates to next state $S'$ exactly at the rising edge of $CLK$.
2. **Next State Logic**: Combinational circuit evaluating Boolean equations $S' = f(S, \text{inputs})$.
3. **Output Logic**: Combinational circuit generating outputs from state (and inputs).

### 8.3 Moore vs. Mealy FSM Architectures

The defining distinction between the two primary FSM classes lies strictly in the inputs to the **Output Logic**:
![](Pasted%20image%2020260925220141.png)
*Figure 8.2: Architectural comparison between Moore and Mealy FSMs. In a Moore machine (top), output logic depends solely on the state register. In a Mealy machine (bottom), output logic receives current state AND external inputs directly (Source: Slide 39).*

#### Architectural Trade-offs

| Criterion | Moore Machine | Mealy Machine |
| :--- | :--- | :--- |
| **Output Dependency** | $\text{Output} = g(S)$ (State only) | $\text{Output} = g(S, \text{Inputs})$ (State + Inputs) |
| **State Diagram Labeling** | Outputs written **inside state circle** ($S / \text{Out}$) | Outputs written **on transition arcs** ($\text{In} / \text{Out}$) |
| **State Count** | Typically **more states** required | Typically **fewer states** required |
| **Output Timing** | Output updates strictly at clock edges | Output updates **immediately** when inputs change |
| **Glitch Sensitivity** | **Glitch-free**; outputs isolated by state register | **Vulnerable to glitches** on input lines propagating to output |
| **Pipeline Integration** | Easily pipelined; one cycle latency | Combinational paths can span across multiple FSMs |

# 9. Comprehensive Design Case Study: Smart Traffic Light Controller

We trace the complete step-by-step engineering design of an intersection controller according to Harris & Harris Section 3.4.1.

### 9.1 Specification
![](Pasted%20image%2020260925220158.png)
*Figure 9.1: Intersection layout of Academic Avenue (East-West) and Bravado Boulevard (North-South), showing traffic lights $L_A, L_B$ and pavement traffic sensors $T_A, T_B$ (Source: Slide 41).*

- **Avenue A (Academic Ave)**: Busy main street.
- **Boulevard B (Bravado Blvd)**: Less busy side street.
- **Inputs**:
  - $T_A$: Traffic sensor on Avenue A (asserted when cars are present).
  - $T_B$: Traffic sensor on Boulevard B (asserted when cars are present).
  - $CLK$: Periodic 5-second tick clock.
  - $Reset$: Synchronous system reset.
- **Outputs**:
  - $L_A$: Traffic light color on Avenue A ($\{\text{Green}, \text{Yellow}, \text{Red}\}$).
  - $L_B$: Traffic light color on Boulevard B ($\{\text{Green}, \text{Yellow}, \text{Red}\}$).
- **Control Policy**:
  - State evaluations occur every 5 seconds.
  - If Avenue A has Green and traffic is present ($T_A=1$), Avenue A **remains Green** indefinitely.
  - When Avenue A has no traffic ($\overline{T_A}$), it transitions through Yellow to Red, granting Green to Boulevard B.
  - Boulevard B holds Green while it has traffic ($T_B=1$). When $\overline{T_B}$, it transitions through Yellow to Red, returning Green to Avenue A.

### 9.2 Black Box Interface
![](Pasted%20image%2020260925220209.png)
*Figure 9.2: Top-level black-box interface for the Smart Traffic Light Controller, defining input control lines and multi-bit output buses (Source: Slide 42).*

### 9.3 State Transition Diagram (Moore Model)

The controller has **4 distinct operating states**:
![](Pasted%20image%2020260925220309.png)
*Figure 9.3: Complete Moore state transition diagram for the Traffic Light Controller. Each state circle shows its name and output light assignments. Directed arcs represent transitions labeled with Boolean trigger conditions (Source: Slide 47).*

- **State $S_0$**: $L_A = \text{Green}$, $L_B = \text{Red}$. (Main street traffic flows).
  - If $T_A = 1$: Loop in $S_0$ ($L_A$ stays Green).
  - If $\overline{T_A} = 1$: Transition to $S_1$ (Avenue A must prepare to stop).
- **State $S_1$**: $L_A = \text{Yellow}$, $L_B = \text{Red}$. (Caution period).
  - Unconditional transition to $S_2$ on next clock cycle.
- **State $S_2$**: $L_A = \text{Red}$, $L_B = \text{Green}$. (Side street traffic flows).
  - If $T_B = 1$: Loop in $S_2$ ($L_B$ stays Green).
  - If $\overline{T_B} = 1$: Transition to $S_3$ (Boulevard B must prepare to stop).
- **State $S_3$**: $L_A = \text{Red}$, $L_B = \text{Yellow}$. (Caution period).
  - Unconditional transition to $S_0$ on next clock cycle.
- **Synchronous Reset**: Forces the controller unconditionally into $S_0$.

$$

| Current State ($S_1 S_0$) | Inputs ($T_A, T_B$) | Next State ($S_1' S_0'$) | Rationale |
| :---: | :---: | :---: | :--- |

### 9.5 Next State Logic Equations

From the transition table, we derive minimal Sum-of-Products (SOP) expressions for next-state bits:

#### Derivation of $S_1'$:
$S_1'$ is asserted in three rows:

$$
\begin{aligned}
S_1' &= (\overline{S_1} S_0) + (S_1 \overline{S_0} \cdot \overline{T_B}) + (S_1 \overline{S_0} \cdot T_B) \\
&= (\overline{S_1} S_0) + S_1 \overline{S_0} (\overline{T_B} + T_B) \\
&= \overline{S_1} S_0 + S_1 \overline{S_0} \\
\mathbf{S_1'} &\mathbf{= S_1 \oplus S_0} \quad \text{(A simple 2-input XOR gate!)}
\end{aligned}
$$
#### Derivation of $S_0'$:
$S_0'$ is asserted in two distinct minterms:

$$
\mathbf{S_0' = (\overline{S_1} \cdot \overline{S_0} \cdot \overline{T_A}) + (S_1 \cdot \overline{S_0} \cdot \overline{T_B})}
$$

### 9.6 Output Encoding & Equations

Lights are encoded using 2 binary bits per light:

$$
\text{Green} = 00_2, \quad \text{Yellow} = 01_2, \quad \text{Red} = 10_2
$$

| :---: | :---: | :---: | :---: | :---: | :---: | :---: |

\mathbf{L_{B1} = \overline{S_1}}

8. **Cycle 9**: Clock edge returns controller to $S_0$. $L_A$ becomes Green again.

# 10. FSM State Encoding Strategies

How binary values are assigned to abstract state symbols dramatically impacts hardware complexity, speed, and power:

| Encoding Style | Definition | Bits for $N$ States | Hardware Characteristics & Trade-offs |
| :--- | :--- | :---: | :--- |
| **Minimal Binary** | Standard base-2 integers (`00`, `01`, `10`, `11`) | $\lceil \log_2 N \rceil$ | **Minimizes flip-flop count**. Next-state logic can become deep and complex for large state counts. |
| **One-Hot** | Exactly one bit asserted per state (`0001`, `0010`, `0100`, `1000`) | $N$ | **Maximizes flip-flops**, but next-state logic reduces to simple OR gates. Ideal for FPGAs with abundant flip-flops. |
| **Output Encoding** | State bits directly match output values | Output width | **Eliminates output logic entirely** ($\text{Output} \equiv \text{State}$). Only valid for Moore machines. |

> [!TIP]
> In custom ASICs where silicon area is dominated by flip-flop cell size, **minimal binary encoding** is preferred. In FPGAs where every logic slice contains dedicated, spare flip-flops, **one-hot encoding** is almost universally selected by synthesis tools to minimize LUT levels and maximize clock frequency.

# 11. Moore vs. Mealy FSM Case Study: The Snail Sequence Detector

A classic DDCA design exercise highlights the architectural differences between Moore and Mealy machines:

> **Problem**: A robotic snail crawls along a paper tape reading a stream of binary digits. The snail must smile ($Y=1$) whenever the sequence **1101** has just appeared.

![](Pasted%20image%2020260925220516.png)
*Figure 11.1: State transition diagrams for the 1101 pattern detector. Top: Moore FSM requiring 5 states ($S_0..S_4$) with outputs labeled inside states. Bottom: Mealy FSM requiring only 4 states ($S_0..S_3$) with outputs labeled on transitions (Source: Slide 89).*

### Trade-Off Breakdown: Snail Detector

1. **State Complexity**:
   - The **Moore machine** requires **5 states**: $S_0$ (Reset), $S_1$ (saw `1`), $S_2$ (saw `11`), $S_3$ (saw `110`), and $S_4$ (saw `1101` $\to$ Smile). It requires 3 flip-flops.
   - The **Mealy machine** requires only **4 states**: The detection of the final `1` is asserted directly on the arc transitioning from $S_3$ back to $S_1$ ($1/1$). It requires only 2 flip-flops.
2. **Reaction Latency**:
   - The **Mealy machine** asserts the smile output **in the very same clock cycle** that the final `1` appears at the input.
   - The **Moore machine** cannot assert the smile output until the **next clock edge** latches state $S_4$, introducing a 1-cycle latency.
3. **Safety / Noise Vulnerability**:
   - The **Moore machine** output is perfectly synchronous and glitch-free.
   - The **Mealy machine** output is combinatorially connected to the input wire; a false noise spike or transient glitch on the tape sensor will directly glitch the smile output.

### How the FSM Drives the Processor
1. **Instruction Fetch**: The FSM directs $\text{PC} \to \text{MAR}$, strobes memory read, and loads the returned instruction into the **Instruction Register (IR)**.
2. **Instruction Decode**: The FSM inspects the 4-bit opcode in $\text{IR}[15:12]$ and branches to specific state sequences.
3. **Execute**: The FSM asserts micro-control signals:
   - Setting `ALUK` to perform addition or bitwise AND.
   - Asserting `LD.REG` to write the ALU output back to the destination register in the Register File.
4. **State Transition to Next Instruction**: The FSM updates the PC and loops back to fetch the next instruction.

# 14. Field-Programmable Gate Arrays (FPGAs)

Presented by Head TA Atabak and TA Maya, this section explores the technology that students use throughout the semester to implement real hardware.

### 14.1 The Hardware Design Spectrum

```
 [ Microprocessors / CPUs ] ──► [ GPUs ] ──► [ FPGAs ] ──► [ Custom ASICs ]
  ◄── Maximum Flexibility                             Maximum Efficiency ──►
  ◄── Software Programmable                          Fixed Silicon Wires ──►
```

- **CPUs / GPUs**: General-purpose hardware executing instruction streams. High flexibility, but significant energy and performance overhead.
- **Application-Specific Integrated Circuits (ASICs)**: Custom silicon fabricated for a single task (e.g., Apple A-series chip, Google TPU). Unrivaled speed and efficiency, but astronomical Non-Recurring Engineering (NRE) costs ($>\$50\text{M}$ for modern mask sets) and completely immutable once fabricated.
- **FPGAs (Field-Programmable Gate Arrays)**: Silicon chips consisting of a sea of uncommitted logic elements and programmable interconnect. They can be reconfigured in milliseconds to become *any* digital circuit—combining hardware acceleration with software-like agility.

### 14.2 Key Applications of FPGAs

1. **Workload Acceleration in Cloud Datacenters**:
   - *Microsoft Project Catapult & Project Brainwave*: Deployed FPGAs in every server across Azure datacenters to accelerate Bing search ranking and deep neural network inference.
   - *Amazon EC2 F1 Instances*: Cloud-accessible UltraScale+ FPGAs for genomics, video processing, and big data analytics.
   - *Genomics Acceleration*: Illumina DRAGEN platforms and Safari Group's *GateKeeper* and *SneakSnake* algorithms use FPGAs to accelerate DNA sequence alignment by orders of magnitude over high-end CPUs.

2. **System Characterization & Memory Research**:
   - SAFARI research group's **SoftMC** (FPGA-based Memory Controller) and **DRAM Bender**: Custom memory test harnesses connected directly to DDR DRAM chips.
   - Led to the discovery and characterization of fundamental hardware security vulnerabilities such as **RowHammer** and **RowPress**, testing of physical unclonable functions (PUFs), and in-memory compute prototypes (PiDRAM).

3. **Architecture Prototyping & Emulation**:
   - Hardware prototypes (e.g., *MetaSys* hardware-software cooperative metadata interface).
   - Barcelona Supercomputing Center (BSC): 96-FPGA emulation farm emulating over 700 million ASIC gates to test novel supercomputer processors before chip tape-out.

1. **Extreme Environments & Field Updatability**:
   - *CERN Large Hadron Collider*: FPGAs handle high-throughput real-time particle collision trigger filtering.
   - *High-Frequency Trading (HFT)*: Financial institutions execute sub-microsecond trading algorithms in FPGA hardware to minimize network-to-execution latency.
   - *Aerospace / Deep Space Missions*: NASA's **Ingenuity Mars Helicopter** utilizes FPGAs for flight control and real-time vision navigation. Reconfigurability allows mission control to route around physical hardware faults induced by cosmic radiation.

### 14.3 Inside an FPGA: Architecture & Primitives

An FPGA is organized as a regular 2D mesh of four fundamental blocks:

```
    ┌────────┐      Vertical Routing Channel      ┌────────┐
    │  CLB   │ ══════════════════════════════════ │  CLB   │
    └────┬───┘                                    └────┬───┘
         │               ┌──────────────┐              │
    ═════╪══════════════ │  Switch Box  │ ═════════════╪═════ Horizontal Channel
         │               │   (S-Box)    │              │
    ┌────┴───┐           └──────────────┘         ┌────┴───┐
    │  CLB   │ ══════════════════════════════════ │  CLB   │
    └────────┘                                    └────────┘
```

1. **Configurable Logic Blocks (CLBs)**: The computational cells, containing:
   - Multiple **Look-Up Tables (LUTs)** implementing arbitrary combinational functions.
   - Dedicated **D Flip-Flops** for registered sequential outputs.
   - Arithmetic carry-chains and local multiplexers.
2. **Switch Boxes (S-Boxes)**: Routing intersections that switch signals between horizontal and vertical wiring channels.
3. **Connection Boxes (C-Boxes)**: Multiplexers and routing switches connecting CLB inputs and outputs to channel wires.
   - Implemented using **pass transistors** (compact, gated by SRAM memory cells) or **tri-state buffers** (higher area cost, but regenerates signal strength across long wires).
4. **Hard Macro Blocks**: High-density silicon IP blocks integrated directly into the fabric:
   - **Block RAM (BRAM)**: Dual-port SRAM blocks for on-chip memory.
   - **DSP Slices**: High-speed dedicated multiply-accumulate (MAC) units.
   - Hard Memory Controllers (DDR4/5) and PCIe interfaces.

> [!IMPORTANT]
> **Interconnect Area Dominance**: In modern FPGAs, **over 80–90% of total silicon area** is consumed by routing channels, programmable switch matrices, and configuration memory. Pure logic (LUTs) accounts for less than 15% of the chip area!

### 14.4 How a Look-Up Table (LUT) Operates

A $K$-input LUT is physically a **$2^K$-to-1 multiplexer** whose data inputs are driven by $2^K$ static SRAM configuration cells:

#### 3-Input LUT Example: Majority Function
Consider implementing the 3-input Majority function:

$$
\text{MAJ}(A, B, C) = 1 \quad \text{if at least two inputs are } 1
$$
| Row | $A$ | $B$ | $C$ | Output | SRAM Cell Value |
| :---: | :---: | :---: | :---: | :---: | :---: |
| 0 | 0 | 0 | 0 | 0 | `SRAM[0] = 0` |
| 1 | 0 | 0 | 1 | 0 | `SRAM[1] = 0` |
| 2 | 0 | 1 | 0 | 0 | `SRAM[2] = 0` |
| 3 | 0 | 1 | 1 | 1 | `SRAM[3] = 1` |
| 4 | 1 | 0 | 0 | 0 | `SRAM[4] = 0` |
| 5 | 1 | 0 | 1 | 1 | `SRAM[5] = 1` |
| 6 | 1 | 1 | 0 | 1 | `SRAM[6] = 1` |
| 7 | 1 | 1 | 1 | 1 | `SRAM[7] = 1` |

- The truth table output column (`00010111`) is written into the 8 SRAM configuration cells.
- The external inputs $A, B, C$ connect to the select lines of the multiplexer.
- When inputs $A=1, B=1, C=0$ are applied, the multiplexer selects `SRAM[6] = 1` and routes it to the output.
- **Any arbitrary 3-variable Boolean function can be realized simply by altering the 8 SRAM bits.**

## 16. Summary & Key Takeaways

### Core Sequential Concepts
- **Gated D Latches** are level-sensitive and transparent when enabled. They cannot safely implement feedback state registers due to race-around hazards.
- **Master-Slave D Flip-Flops** isolate inputs from outputs by cascading two oppositely clocked latches. They sample strictly at the **rising clock edge**, establishing deterministic synchronous execution.

### FSM Principles
- An FSM is partitioned into **Next State Logic**, **State Registers**, and **Output Logic**.
- **Moore Machines**: Outputs depend solely on current state ($Y = g(S)$). Immune to input glitches; outputs change only at clock edges.
- **Mealy Machines**: Outputs depend on state and inputs ($Y = g(S, X)$). React faster and require fewer states, but outputs can glitch if inputs change asynchronously.
- State encoding involves engineering trade-offs: **Binary** minimizes flip-flops; **One-Hot** minimizes combinational logic depth and dominates FPGA implementations; **Output Encoding** eliminates output logic entirely.

### Real-World Execution
- The **Control Unit** of every general-purpose microprocessor (e.g., LC-3) is fundamentally an FSM coordinating datapath multiplexers, ALUs, and registers.
- **FPGAs** provide reconfigurable hardware acceleration through Lookup Tables (LUTs) and programmable routing matrices, serving as the bridge from logic theory to working silicon.
