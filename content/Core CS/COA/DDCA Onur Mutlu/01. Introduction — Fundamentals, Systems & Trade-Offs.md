# 1. Motivation: Why Do We Have Computers?

### 1.1 The Ultimate Purpose of Computing
Computers do not exist simply to calculate numbers; they exist to **solve problems** and help humans **gain insight**.

> *"The purpose of computing is [to gain] insight, not numbers."*  
> — **Richard Hamming**, *Numerical Methods for Scientists and Engineers* (1962)

- **Number crunching as a means to an end**: In modern applications—such as Large Language Models (LLMs), genomic sequencing, autonomous driving, and climate modeling—systems execute trillions of matrix-vector multiplications and arithmetic operations. However, this arithmetic is merely intermediate computation. The ultimate goal is extracting actionable, reliable insight.
- **Guiding objective**: Enable a fundamentally better future and advance human capability through technology.

### 1.2 How Computers Solve Problems: Orchestrating Electrons
In all dominant modern computing technologies, problem solving is achieved by **orchestrating electrons** across semiconductor devices:
- Information is represented by physical charges, potentials, and currents.
- Computation occurs by directing electron flows through switching circuits.

#### The Communication Barrier
Humans cannot communicate natively in the "language of electrons". A programmer cannot instruct individual electrons to move between physical conductors to perform an addition or an algorithm. To bridge this vast semantic gap between high-level human problem formulation and microscopic physical electron manipulation, computer engineers invented **the transformation hierarchy**.

# 2. The Transformation Hierarchy

The transformation hierarchy consists of discrete layers of abstraction. Each layer translates the problem downward into progressively lower-level representations until physical devices act upon electrons.
![](Pasted%20image%2020260924131933.png)
*Figure 2.1: The Levels of Transformation Hierarchy connecting problems to electrons*

### 2.1 Levels of the Stack (Top to Bottom)

1. **Problem**:
   - Formulated by humans in natural language or domain-specific mathematical formulations (e.g., "classify this protein structure", "navigate a car autonomously").
2. **Algorithm**:
   - A step-by-step procedure guaranteed to solve the problem with three essential properties:
     - **Finiteness**: Guaranteed to terminate after a finite number of steps.
     - **Definiteness**: Each step is unambiguously and precisely stated.
     - **Effective Computability**: Each step can be realistically carried out by a computing machine.
   - *Key Insight*: Many distinct algorithms can solve the same problem, each exhibiting distinct computational complexities, memory footprints, and parallelizability.
1. **Program / Language**:
   - The algorithmic procedure expressed in human-readable, formal programming languages (e.g., C, C++, Python, Java, PyTorch).
4. **System Software**:
   - Compilers, Operating Systems (OS), Virtual Machines (VM), and Memory Managers (MM).
   - Translates high-level programming constructs into machine-level instructions, schedules tasks, manages physical memory, and multiplexes underlying hardware resources.
1. **SW/HW Interface — Instruction Set Architecture (ISA)**:
   - The formal **contract / interface** between software and hardware.
   - Defines everything a programmer (or compiler) needs to know to write functional machine code: instructions, addressing modes, register states, memory organization, and interrupt behavior.
   - What the programmer assumes the hardware will satisfy, and what the hardware promises to execute.
   - *Examples*: x86, ARM, RISC-V, MIPS, LC-3b.
1. **Microarchitecture**:
   - The concrete internal hardware implementation of an ISA.
   - *Crucial Distinction*: An ISA defines **what** operations must be supported; the microarchitecture defines **how** those operations are executed in hardware.
   - A single ISA can have dozens of radically different microarchitectures:
     - High-performance out-of-order superscalar design (e.g., Intel Core i9, AMD Zen 4).
     - Low-power, simple in-order design (e.g., Intel Atom, ARM Cortex-A53).
     - Both run the exact same binary executable code without modification.
7. **Digital Logic Circuits (Logic)**:
   - The functional building blocks of the microarchitecture.
   - Composed of combinational logic (e.g., ALUs, multiplexers, decoders) and sequential logic elements (e.g., registers, latches, flip-flops, finite state machines).
1. **Devices**:
   - The physical electronic switches and components that implement logic gates.
   - In modern computers, these are **Metal-Oxide-Semiconductor Field-Effect Transistors (MOSFETs)** (specifically nMOS and pMOS complementary pairs, forming CMOS circuits).
1. **Electrons**:
   - Governed by the laws of quantum mechanics and solid-state physics.

# 3. Computer Architecture: Narrow View vs. Expanded View

Traditionally, computer architecture was viewed narrowly. However, modern challenges demand an expanded perspective.
![](Pasted%20image%2020260924132409.png)
*Figure 3.1: The traditional Narrow View vs. the modern Expanded View of Computer Architecture*

### 3.1 The Narrow View
- Restricts computer architecture strictly to the **Instruction Set Architecture (ISA)** and the **Microarchitecture** (with digital logic circuits).
- Assumes a rigid abstraction boundary: software developers write code without regard for hardware details, and hardware engineers design processors without knowledge of specific application algorithms.

### 3.2 The Expanded View & Cross-Layer Co-Design
- Encompasses the entire stack from **Algorithms down to Devices**.
- **Axiom of Architecture**:
  > *To achieve the highest energy efficiency, performance, and robustness, we must take the expanded view of computer architecture and co-design across the hierarchy (from algorithms to devices), specializing as much as possible within the design goals.*

#### Why the Narrow View Breaks Down
1. **The End of Classical Scaling**: Dennard scaling (constant power density with shrinking transistors) collapsed around 2005. Moore's Law scaling is slowing and becoming economically prohibitive.
2. **The Memory Wall**: Moving data from off-chip memory to processing cores consumes orders of magnitude more energy and time than computing on that data.
3. **Emergence of Massive Workloads**: Workloads such as LLM training/inference and genomic analysis require speedups that general-purpose hardware cannot deliver without application-specific architectural adaptations.

### 3.3 Synergies: Hardware, Software, and System Thinking
- **Bidirectional Advantage**:
  - Understanding hardware allows programmers to write software that leverages memory hierarchies, vector lanes, and cache line boundaries.
  - Understanding software allows hardware architects to design microarchitectures tailored to actual memory access patterns, branch behaviors, and data dependencies.
- **Universality of Architectural Concepts**:
  Concepts originating in computer hardware recur across systems and software engineering:
  - *Pipelining*: Decomposing a task into sequential stages to increase throughput.
  - *Out-of-Order Execution*: Scheduling independent sub-tasks dynamically whenever dependencies are resolved.
  - *Caching*: Storing frequently used items close to the consumer.
  - *Prefetching*: Anticipating future needs and loading data in advance.
  - *Speculative Execution*: Performing work proactively based on historical prediction before verifying if the result is needed.

### 3.4 "Plenty of Room at the Bottom" vs. "Plenty of Room at the Top"

```
          [ Algorithms / Software / Compilers ]  --> "Plenty of Room at the Top"
                            ↕ (Cross-Layer Optimization)
          [ Microarchitecture / Circuits / Devices ]  --> "Plenty of Room at the Bottom"
```

1. **Plenty of Room at the Bottom**:
   - Proposed by **Richard Feynman** in his famous 1959 lecture (*"There's Plenty of Room at the Bottom"*).
   - Envisioned manipulating individual atoms, creating nano scale computing structures, and engineering quantum machines.
   - Pushing device physics, new materials (e.g., FinFET, Gate-All-Around transistors, High-k metal gates), and extreme ultraviolet (EUV) lithography continues to unlock device-level gains.
1. **Plenty of Room at the Top**:
   - As hardware scaling encounters thermal and physical barriers, massive opportunities exist in optimizing algorithms, languages, compilers, and hardware specialization (Leiserson et al., *Science* 2020).
1. **The Architectural Synthesis (Axiom Revisited)**:
   - There is plenty of room both at the top and at the bottom, **but much more so when you communicate well between and optimize across the top and the bottom**.

# 4. Definition and Design Goals of Computer Architecture

### 4.1 Formal Definition
> **Computer Architecture** is the science and art of designing, selecting, and interconnecting hardware components and designing the hardware/software interface to create a computing system that meets functional, performance, energy consumption, cost, and other specific goals.

- **Why Science?** It relies on quantitative measurement, empirical bench marking, formal models, and the scientific method.
- **Why Art?** Architects must make multi-variable trade-offs in the face of uncertainty. A chip conceived today will execute software written five to ten years in the future on workloads that do not yet exist.

### 4.2 The Multi-Metric Trade-Off Space
No computer architecture is universally "optimal". Every processor is an optimization balance point across competing metrics:

```
                      Performance (Latency, Throughput)
                                    /\
                                   /  \
                                  /    \
            Energy & Power (TDP) /______\ Cost & Form Factor
                                 \      /
                                  \    /
                                   \  /
                                    \/
                Robustness (Safety, Security, Reliability) & Sustainability
```

1. **Performance**:
   - *Latency (Execution Time)*: Time elapsed from start to completion of a task.
   - *Throughput*: Number of tasks or instructions completed per unit time.
2. **Energy and Power**:
   - *Power (Watts)*: Rate of energy consumption; dictates heat dissipation, cooling requirements, and Thermal Design Power (TDP).
   - *Energy (Joules = Power × Time)*: Total energy consumed; directly determines battery life in mobile systems and electricity operational expenditure in hyperscale data centers.
1. **Cost and Form Factor**:
   - Die area (larger chips have exponentially lower manufacturing yield), packaging, printed circuit board (PCB) footprint, cooling assembly, and target retail price.
4. **Robustness (Security, Safety, Reliability, Availability, Predictability)**:
   - *Security & Privacy*: Resilience against hardware-level attacks, side channels, and unauthorized information leakage.
   - *Reliability & Fault Tolerance*: Correct operation despite cosmic ray strikes, transistor aging, electromagnetic interference, and manufacturing defects.
   - *The "Fail-Fast" Principle*: If hardware experiences a fault and cannot guarantee correctness, it should fail immediately and notify the system, rather than silently propagating corrupted data.
   - *Redundant Execution Trade-off*: Running identical computations redundantly (e.g., dual-modular or triple-modular voting) drastically reduces error probability, but doubles or triples energy consumption and hardware cost.
5. **Sustainability**:
   - The environmental footprint of computing: raw material extraction, fabrication chemicals, water usage, embodied carbon of silicon production, and multi-megawatt operational power draw.
6. **Programmability and Usability**:
   - The developer time required to map new algorithms onto the hardware architecture.

# 5. Modern Computing Landscape: Precedents & Case Studies

To understand modern architectural trade-offs, the lecture analyzes state-of-the-art industry and academic systems.

### 5.1 Heterogeneous Systems-on-Chip (SoC)
Modern microprocessors are no longer homogeneous single-core or multi-core CPUs. They integrate specialized, domain-tailored accelerators alongside general-purpose processing cores onto a unified silicon die.
![](Pasted%20image%2020260924132815.png)
*Figure 5.1: Apple M1 Ultra System Organization: SoC with compute & caches, unified main memory, storage, and sensors*
![](Pasted%20image%2020260924132918.png)
*Figure 5.2: Apple M1 Processor Floorplan: Heterogeneous compute elements including Firestorm performance cores, Icestorm efficiency cores, 8-core GPU, system-level cache (SLC), and 16-core Neural Engine*

- **Apple M1 / M1 Ultra Case Study**:
  - **High-Performance Cores ("Firestorm")**: Deep pipelines, wide superscalar dispatch, aggressively tuned for maximum single-threaded IPC (instructions per cycle).
  - **High-Efficiency Cores ("Icestorm")**: Compact, power-sipping cores handling background OS tasks with minimal energy draw.
  - **Domain Accelerators**: Integrated GPU for parallel graphics/compute, 16-core Neural Engine for AI inference, dedicated video encode/decode blocks, and secure enclaves.
  - **Unified Memory Architecture (UMA)**: Compute cores and accelerators share wide, high-bandwidth on-package LPDDR memory channels, eliminating the energy-intensive overhead of copying buffers across peripheral buses.

### 5.2 Domain-Specific Accelerators (AI / ML)

#### A. Google Tensor Processing Unit (TPU)
- Tailored specifically for deep neural network inference and training.
- Centered on a **Systolic Array Matrix Multiply Unit (MXU)**:
  - Instead of reading and writing intermediate values back to a central register file or memory for every operation, data streams through a 2D mesh of multiply-accumulate (MAC) processing elements.
  - Intermediate partial sums flow directly from one cell to its neighbor, drastically reducing register file read/write energy and maximizing data reuse.
![](Pasted%20image%2020260924133043.png)
*Figure 5.3: Google TPU Printed Circuit Board and the 2D Systolic Array Matrix Multiply dataflow*

#### B. Tesla Full Self-Driving (FSD) and Dojo
- **Tesla FSD Board**: Designed for autonomous driving where safety is non-negotiable.
  - Features **two redundant chips** executing identical perception models side by side. If one chip fails or outputs an anomaly, the redundant backup guarantees fail-operational behavior.
- **Tesla Dojo**: End-to-end vertical co-design spanning from custom silicon chips up through modular compute tiles, rack cabinets, custom network interconnects, and dedicated PyTorch compiler stacks.
![](Pasted%20image%2020260924133124.png)
*Figure 5.4: Tesla Dual-Chip Full Self-Driving (FSD) board featuring redundant silicon for safety-critical execution*
![](Pasted%20image%2020260924133210.png)

#### C. Cerebras Wafer-Scale Engine (WSE-2 / WSE-3)
- Conventional chips are cut from a 300 mm silicon wafer into hundreds of small rectangular dies.
- Cerebras manufactures the **entire 300 mm wafer as a single contiguous chip**:
  - **WSE-2**: 46,225 mm² area, 2.6 trillion transistors, 850,000 AI-optimized cores, and 40 gigabytes of on-chip SRAM.
  - **Motivation**: Eliminates the catastrophic latency and power penalty of off-chip bus communication by keeping trillions of operations and tens of gigabytes of model parameters on a single silicon substrate.

### 5.3 Processing-in-Memory (PIM) / Near-Data Processing
In conventional computer systems (von Neumann architecture), memory and computation are separated by a narrow bus:

```
  [ Processor (CPU/GPU) ] <==== High-Latency / High-Energy Bus ====> [ Main Memory (DRAM) ]
                                (Data Movement Bottleneck)
```

- **The Problem**: A high percentage of total system execution time and energy is expended merely shuffling bits between DRAM chips and processor registers. In data centers, memory accounts for over 60% of total system hardware cost.
- **The Solution (PIM)**: Integrate compute logic directly inside or adjacent to the memory dies. Compute on data *where it resides* rather than moving data to the CPU.
![](Pasted%20image%2020260924133400.png)
*Figure 5.7: Processing-in-Memory (PIM) server architecture with host CPUs, standard DRAM, and PIM-enabled DIMMs (Source: Slide 76).*
![](Pasted%20image%2020260924133438.png)
*Figure 5.8: Samsung AxDIMM architecture accelerating deep learning recommendation models (DLRM) near memory (Source: Slide 80).*

- **Real-World PIM Systems**:
  - **UPMEM Processing-in-DRAM (2019)**: Commercial DDR4 R-DIMM modules containing 128 programmable general-purpose DRAM Processing Units (DPUs) embedded directly inside DRAM chips.
  - **Samsung AxDIMM & HBM-PIM (2021)**: Near-memory processing buffers placed on DIMMs to accelerate personalized recommendation systems (DLRM) and tensor pipelines.
  - **SK Hynix AiM (Accelerator-in-Memory, 2022)**: High-bandwidth memory incorporating in-situ arithmetic logic units for large language model inference.

# 6. The Fundamental Components of a Computer

Dating back to the foundational work by Arthur Burks, Herman Goldstine, and John von Neumann (1946, *Preliminary Discussion of the Logical Design of an Electronic Computing Instrument*), a computer consists of three core components:

```
  +-------------------------------------------------------------+
  |                        PROCESSING                           |
  |  +--------------------------+  +--------------------------+ |
  |  |    Control (Sequencing)  |  |         Datapath         | |
  |  +--------------------------+  +--------------------------+ |
  +------------------------------▲------------------------------+
                                 │
                                 ▼ (Bidirectional)
  +-------------------------------------------------------------+
  |                 MEMORY (Program and Data)                   |
  +------------------------------▲------------------------------+
                                 │
                                 ▼ (Bidirectional)
  +-------------------------------------------------------------+
  |                      INPUT / OUTPUT (I/O)                   |
  +-------------------------------------------------------------+
```
![](Pasted%20image%2020260924133549.png)
*Figure 6.1: The classical von Neumann model: Processing (Control and Datapath), Memory, and I/O (Source: Slide 124).*

1. **Processing**:
   - **Datapath**: The execution hardware (registers, ALUs, multipliers, shifters) that operates on data.
   - **Control (Sequencing)**: The logic that interprets instructions, sequences execution phases, and generates control signals for the datapath.
1. **Memory / Storage**:
   - Stores both the instructions to execute (**program**) and the operands being operated on (**data**).
   - Unified storage of program and data in the same memory space is the hallmark of the **von Neumann architecture**.
3. **Communication / Input-Output (I/O)**:
   - Interfaces the processing and memory subsystems with the outside world (disks, networks, user displays, sensors, accelerators).

# 7. Spectrum of Computing Platforms: General-Purpose vs. Special-Purpose

### 7.1 The Fundamental Trade-Off: Flexibility vs. Efficiency
There is an unavoidable engineering trade-off between how versatile a system is and how efficiently it computes:

```
  High Flexibility ◄────────────────────────────────────────► Peak Efficiency
  Easy Programming                                            Fixed Hardware
  Suboptimal Peak Efficiency                                  Extreme Performance
  
  [ Microprocessors (CPUs) ] ───► [ FPGAs ] ───► [ ASICs (Accelerators) ]
```

#### The Wrench Analogy
Prof. Mutlu illustrates this trade-off using mechanical tools:
![](Pasted%20image%2020260924133726.png)
*Figure 7.1: The tool analogy: An adjustable wrench (general purpose) vs. dedicated fixed-size wrenches (special purpose) (Source: Slide 133).*

- **General-Purpose System (Adjustable Crescent Wrench)**:
  - Can adjust to turn almost any bolt size.
  - Very flexible and convenient; you only need to carry one tool.
  - *Shortcoming*: It has loose tolerances, can slip, rounds off bolt edges, and transfers torque inefficiently. It is never the optimal tool for any specific bolt.
- **Special-Purpose System (Fixed Combination Wrench)**:
  - Designed precisely for a single metric bolt size (e.g., 10 mm).
  - Delivers maximum torque transfer, perfect fit, and highest mechanical efficiency.
  - *Shortcoming*: Completely inflexible. If you encounter an 11 mm bolt, the tool is useless.

## 8. Fundamental Design Principles & Methodologies

Throughout the introductory lecture, several recurring principles of computer engineering are established:

### 8.1 Critical Trade-Off Analysis
Every architectural choice involves a trade-off. An architect cannot maximize throughput without impacting area, thermal limits, or circuit complexity. When evaluating any architectural proposal, ask:
1. What is the fundamental bottleneck being solved?
2. What are the performance, energy, area, and complexity costs introduced?
3. How does this hardware change affect the software compiler and runtime system?

### 8.2 Speculative Execution and Last-Time Prediction
- **Definition**: Performing an operation *before* knowing with certainty whether the operation is needed or what its input values will be.
- **Everyday Analogy**: Carrying an umbrella when leaving home because the sky looked gray yesterday and it rained. You speculate based on past observation to avoid getting wet.
- **Hardware Application**:
  - *Branch Prediction*: Modern processors predict which way an `if-else` branch will jump before the condition is calculated, executing instructions down the predicted path speculatively.
  - *Data Prefetching*: Observing memory access strides and fetching cache lines from DRAM before the CPU issues load requests.
  - *Core Concept*: Exploits temporal and spatial regularity to hide pipeline latency.

### 8.3 Hardware Fault Handling: Fail-Fast vs. Redundancy
- **Fail-Fast**: Hardware must detect corrupted data immediately (e.g., via parity or ECC) and raise an exception rather than silently propagating invalid state to software.
- **Redundant Voting**: Systems operating in safety-critical environments (e.g., Tesla FSD, aerospace) run parallel redundant hardware engines and vote on results to tolerate transient faults.

### 8.4 The Primacy of Energy and Sustainability
Historically, performance was the primary design driver. Today, power dissipation, thermal limits, and environmental sustainability dictate architectural decisions. Moving data is the most expensive operation in modern silicon; architectures that minimize data movement (e.g., PIM, systolic arrays, deep cache hierarchies) represent the forefront of system design.
