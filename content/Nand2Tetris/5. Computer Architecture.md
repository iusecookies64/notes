## Von Neumann Architecture

As seen earlier in this course, **Alan Turing** created theoretical model of **Universal Turing Machine**, which is a single general purpose computing machine. This model was practically implemented by **Von Neumann**, the general architecture of the machine is shown below.

![[Pasted image 20250125104012.png]]

The idea is that we will input the computer program into the memory, and then CPU will execute the program line by line and give output. The memory also stores data besides the program.

Let's now understand this architecture in more detail. To understand the architecture in detail, we need to understand what types of information flow from side to side in the computer.

![[Pasted image 20250125105549.png]]

High level there are three types of information that flows through different part of the computer.
- **Data Bus:** the data i.e. binary numbers that we want to perform the operation on will be taken from memory to register and then from register to the ALU. The ALU will then perform some operation on these numbers (add, subtract, AND, OR, etc) and return the output.
- **Address Bus:** now which address are we currently reading/writing the data from the memory is transferred using another set of wires called address bus.
- **Control Bits/Bus:** the set of wires that specify the operation to perform flow through the control bus, sometimes called the control bits.

Let's now talk about the individual parts of the computer.
- **ALU:** the most simplest part is the ALU, it takes input from data bus and control bus and puts the output back into the data bus and control bus. The control bus takes output like whether the result is negative or whether the result is zero (as seen in the ALU chip we designed).
- **Registers:** the register takes data from data bus and stores them, it can also put data into the data bus and along with address to store it in the ram. There are some registers that just store the address of what piece of memory are we currently pointing to. Hence registers also feed into address bus.
- **Memory:** The memory is connected with address bus that specifies from where to read or write the data. It is also connected to the data bus which will either read the the current address data, or will write data to current address. 
	- If we look a little closer, there are two types of information in the memory, first the data (i.e. binary numbers) and second is the program.
	- When we want to read the data we specify it's address and read it from the ram, and when we want to read the program, we specify its address and read it from the rom.
	- Sometimes the instructions contain bits that specify the type of operation to perform, hence we also feed the output of the memory into control bus.

## The Fetch-Execute Cycle

The basic CPU loop is fetching an instruction, then executing it and then fetch another instruction, execute it and so on. Let's look at these two cycles one by one.
#### Fetching

The steps that take place in this cycle are,
- Put the location of the instruction into the "address" of the memory. This location of which instruction to execute next, is stored in a register in the CPU which is called the **Program Counter**.
- Get the instruction code itself by reading the memory contents at that location.
#### The Program Counter

- When we want to read the next instruction, we either increase the value in program counter register by 1 or put a new value in case of jumps. 
- This new value of program counter is fed into the address of the program memory.
- The output of the memory is read as the next instruction code that we need to execute.

![[Pasted image 20250125131921.png]]
#### The Execute Cycle

- The instruction that is read specifies "what to do"
	- Which arithmetic/logical operation to perform.
	- What memory to access (read/write).
	- If/where to jump.
- Often different subsets of the instruction bit controls different aspects of the operation.
- Executing the operation involves also accessing registers and/or data memory.

Now how exactly this is done differs from computer to computer, we will learn how this is done in the context of the hack computer.
#### Fetch-Execute Cycle Clash

If we look closely, both the instruction and the data resides in the memory, in the fetch cycle we provide the address of the program counter, and in execute the cycle the address of the data is provided. 

Now when executing we need the value of the instruction as well as the data, this is a clash. Also we need a way to differentiate the address that is for data and the address that is for the instruction, because both of them need to be connected to the same address input pins of the memory. 

![[Pasted image 20250125134613.png]]

The fix to be able to differentiate between instruction and data addresses is simple, we will use a multiplexor which will take the instruction address in the fetch cycle and will take in the data address in the execute cycle.

The fix for output of instruction and data being the same is that we know that fetch and execute are done one after the other, hence in the execute cycle we will get the instruction code output, we will store this in a register called instruction register which loads the output of memory in fetch cycle. Then in the execute we can read instruction from this register and data directly from the memory register.

The final architecture with these solutions is shown below.

![[Pasted image 20250125140347.png]]

**Simple Solution: Harvard Architecture**
A simple solution to the above problem is that we keep 2 separate memories, one for program and another for data, both will have their own address input and output. This architecture is called the **Harvard Architecture**, but mostly it is called a variant of Von Neumann Architecture.

## Hack Central Processing Unit And Computer

We will now understand how the hack cpu exactly works. Before that let's look at the cpu abstraction.

It is a 16-bit processor designed to:
- It executes the current instruction in the instruction register.
- Figures out which instruction to execute next.
#### Hack CPU Interface

The cpu doesn't work on its own, it has to take input from the other devices in the computer and then give output which other devices can take.

![[Pasted image 20250125172439.png]]

Below is the exact specification of the interface of the hack cpu interface.

**Input Specifications**
- `inM`: There is a 16-bit data memory input pin, which is the value of the current selected memory register. There is always some register selected in the memory, and this input pin gives that value.
- `instruction`: Next is a 16-bit instruction memory input which gives the current instruction to execute. At any moment just like there is always a selected register in the memory, there is a instruction present in the instruction memory.
- `reser`: Reset pin, that comes from the user, which tells to reset the program counter.

**Output Specifications**
- `outM`: The output of the operation, that we have to write to the memory.
- `writeM` This is the load bit, that enables the memory for the write operation.
- `addressM`: This is the address of the memory where we want to write the output of the calculation.
- `pc`: The address of the next instruction that we have to fetch in the next cpu cycle.

###### The A Register
Let's start with the first part of the hack cpu, which is the `A` Register part.

![[Pasted image 20250125185400.png]]

- The MUX switch before A register takes in two input, one is the current intersection value and other is the output of the previous ALU computation.
- When the left most bit of the instruction is `0`, then it is an A instruction and we have to load the value of instruction into the A register.
- When the left most bit is 1, then the instruction is composed of multiple parts as discussed before, they are show below.

![[Pasted image 20250125190655.png]]

- In case of C instruction, the mux simply ignores the instruction value and takes in the output of the ALU.
- Note: there is another load bit over the A register, this bit actually decides whether to actually load the input into the memory or not. This load bit is 1, if either op-code of instruction is 0, or the left most bit in the **Destination Load Bits** is `1`. Destination load bits correspond to ADM correspondingly.
- Note: output of the A register is also connected to one of the output of the cpu i.e. the `addressM` output pin which specifies the address where to write the output.
###### The ALU Part
Let's now understand the ALU part of the cpu.

![[Pasted image 20250125193934.png]]

- First we see that the ALU directly receives one input from the D register.
- Then it conditionally accepts the input from A register or the `inM` based on the `a` code in the **comp bits** of the instruction.

![[Pasted image 20250115082918.png]]

- The ALU receives the control bits from the instruction that tells it what computation to preform.
- The ALU gives output of the computation and also returns two bits `zr` and `ng` which tell, if the output is `0` or if the output is `-ve`.
- The output of the ALU if fed into each of A, D, and M registers and whether to load the registers with the output or not is decided by the `dest` bits in the instruction. From the above diagram `d1 -> A`, `d2 -> D` and `d3 -> M`.
###### The Program Counter
It is a register that stores the location of the instruction to execute. Let's understand how it works.

![[Pasted image 20250125194213.png]]

- The PC initially has the value `0` (i.e. when the user starts the computer). Then in every cpu cycle if all three of the jump bits are `0`, then it simply increments the previous value by 1.
- If all of the jump bits are `1`, then it loads the value of the `A` register.
- In other cases, if the condition is met, then it performs goto, otherwise will do `PC++`.
- The PC Logic is as follows.
```
// PC Logic:
if (reset == 1) PC = 0
else:
	// calculate loads
	loads = f(jump_bits, ALU output controls)
	if (loads == 1) PC = A
	else PC++
```
- The `f` function is a black box for now, this is something which we have to implement in this weeks project.
