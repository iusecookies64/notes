## Overview

The modern day computer does a lot of things i.e. runs different apps, plays video/audio etc. Even if the we can do a lot of these things on the computer, the hardware that performs these operation is same.

In this unit we will learn how to make the same hardware perform different tasks.

In early 20th century Alan Turing tried to formalise the notion of a computing machine, he made multiple models each of which performed specific set of tasks. Then he noticed that we can make a single machine (Universal Turing Machine) that could perform all of these tasks, given the right set of instructions.

The same idea was later turned into practice by Von Neumann, who built the first serious architecture of a general computing machine. The centre piece of his architecture was that we will have the program stored in a hardware (ROM), the computer with then according to the software stored in the hardware.

Hence, different programs can make hardware perform different functionality.

Let's look at how general purpose computer would work.

![[Pasted image 20250114182913.png]]

The program will first be stored in the computer memory. A program is nothing but a sequence of binary instructions that the computer understands. The cpu then reads the instructions one by one and perform the instructions.

The behaviour of the cpu thus is dependent on the program that it is running.

There few elements to this:
1. The first how do we specify the instructions and what exactly does the instruction asks the computer to do.

3. The next thing is we need to tell the hardware what to operate on i.e. it knows what operation to do, but on what data we need to do this operation we need to specify that also.

Now, in real world, we never have to write instructions in machine language. We normally code in high level languages which are then converted to machine instructions by another program called compiler.

## Machine Language Element's

#### Machine Language

- It is the specification of the Hardware/Software Interface.
	- What are the supported operations?
	- What do they operate on?
	- How is the program controlled?
- Usually machine language is made in close correspondence to actual Hardware Architecture.
	- Not necessarily though, sometimes we add extra functionality to make it easier for compiler writers.
- The more complicated data types that the machine language operates on the more costly it will be to make the hardware. Cost in terms of 
	- Silicon Area
	- Time to Complete Instructions.

#### Machine Operations

- Usually these correspond to what's implemented in the Hardware.
	- Arithmetic Operations: add, subtract, ...
	- Logical Operations: and, or, ...
	- Flow Control: "goto instruction X", "if C then goto instruction Y"
- Different machine languages differ between on,
	- Richness of the set of operations (division? bulk copy? ...)
	- Data types (width (8-bit, 64-bit), floating point, ...)

## Addressing

One important thing in machine languages is how do we specify address of data to perform the operation on.

The main problem here is that accessing memory location is expensive,
- We long addresses if the memory capacity is large.
- Getting the memory contents into the cpu takes time.

The solution to both of these problems is **Memory Hierarchy**.

![[Pasted image 20250114210641.png]]

We have different level's of memory, starting from the memory that is present in the cpu itself, called **Registers**. This is the fastest memory made using expensive technology, then we have **Cache** memory, then **RAM**, and finally the **Disk**. As we move down in the Hierarchy the capacity usually keeps increasing and the speed keeps decreasing.

For now we will only discuss about how do we handle the memory that is present inside of the cpu, we call them **Registers**.

There are two types of Registers:
- **Data Registers**: these can store data that cpu directly uses for it's calculation. CPU can directly refer to these addresses by name.
- **Address Registers:** these are registers that store address of memory that we need to read/write.

![[Pasted image 20250114211845.png]]
#### Addressing Modes

There are many possible in which data might be accessed by the cpu.

- Directly access data from a register.
```
Add R1, R2                    // R2 <- R2 + R1
```

- Direct Access:
```
Add R1, M[200]                // Mem[200] <- Mem[200] + R1 
```

- Indirect Access:
```
Add R1, @A                    // Mem[A] <- Mem[A] + R1
```

- Immediate:
```
Add 73, R1                    // R1 <- R1 + 73
```

#### Input / Output

Input / Output devices are usually connected to some fixed memory addresses.

For example input busses from mouse might be connected to some fixed memory location and whenever mouse moves, the value stored in this register also changes.

Now what is the meaning of the value stored in this address is something specified by a software called "Drivers" which know the location of the address as well as what is the meaning of the value stored in that address.

#### Flow Control

Usually the CPU executes machine instructions in sequence. But sometimes we need to "jump" unconditionally to another location, e.g. so we can loop.

One way is that we directly specify the jump command that makes the program to specified instruction.

```
101. Load R1, 0
102. Add 1, R1
	 ...
...  // Do something with R1's value
	 ...
156. Jump 102
```

Note that here the instruction number e.g. 102 is not that important, what is important is that the instruction moves to where we intend it to move, because it might happen that after this program is compiled to assembly the line numbers might change. Hence we use symbolic form as shown below.

```
101. Load R1, 0
Loop: Add 1, R1
	 ...
...  // Do something with R1's value
	 ...
156. Jump Loop
```

>[!Note]
>The exact syntax to specify symbols might be different for different machine languages.

Some times we need to jump conditionally as shown below.

```
	 JGT R1, 0, cont           // Jump to cont if R1 > 0
	 Subtract R1, 0, R1        // R1 <- 0 - R1 (making R1 positive)
cont:...
	 // Do something with positive R1
```

#### Hack Computer: Hardware

It is a 16-bit machine consisting of:

- **Instruction Memory (ROM):** a sequence of 16-bit registers i.e. `ROM[0], ROM[1], ...`

The flow of hack machine is as follows,
- The ROM is loaded with a hack program

#### Hack Computer: Registers

The hack machine language recognises three registers:
- **D** register hold's a 16-bit value, it is a data register
- **A** register hold's a 16-bit value, it is an address register, but can be used as a data register as well
- **M** represents the 16-bit RAM register addressed by A. Our RAM may have any number of registers, but at a time only one of them will be selected.

## Hack Instructions

Let's look the two types of instructions that we have in the hack machine language.
#### The A-Instruction

This instruction is primarily used to set value into the A register. The syntax of setting value to A register is `@value`, where value is either:
- a non-negative decimal constant or
- a symbol referring to such a constant

This sets the value of A register and has a side effect of `RAM[A]` getting selected into the RAM register.

#### The C-Instruction

This is where the action happens, this instruction always does one of the many predefined computation and then it may store the result of computation in one or more of the registers, it may jump to a instruction the syntax is as follows.

```
dest = comp ; jump                // both dest and jump are optional
```

The possible values of `dest`, `comp` and `jump` are given below.

![[Pasted image 20250114225037.png]]

- The `comp` instruction can compute one of the listed operations.
- The `dest` instruction can null, or we can assign the result of the computation into any of the register, even multiple registers at a time.
- The `jump` instruction always compares the result of `comp` to `0`, for example `JGT` means jump if greater than `0`. The program will jump to instruction `ROM[A]`.

Example: write a program that jumps to `ROM[56]` if `D-1 == 0`.

```
@56                        // A = 56
D-1;JEQ                    // if (D-1 == 0) goto 56
```

## Input / Output

Now let's learn how we use machine language to control and manipulate IO devices. Here we will discuss how display device and keyboard are used with the hack computer.

When using high level languages (java, python, ...) we have access to rich libraries that allows us to interact with IO devices. But in a low level machine language, all we have is bits.

#### Hack Platform Display Output
###### Screen Memory Map
It is designated memory area, dedicated to manage a display unit. The physical display is continuously refreshed from the memory map, many times per second. Hence if we make changes to the bits in the screen memory map, then we can hope that the next time the display refreshes, these changes reflect on the screen.

In our computer we will have a `256 x 512` pixels black and white display. Since the display is b/w we can have a single represent the state of a pixel on the screen. 

![[Pasted image 20250115090909.png]]

The total number of pixels in our screen are `256 * 512 = 131072`, in our system we only have 16-bit registers, hence we would need `131072 / 16 = 8192` registers to store the entire screen. 

Hence we would have `8192` registers starting from some fixed register that we will call out Screen Memory Map.

This also means that in order to change a given pixel, we must find inside of which word it will be present and then get that entire 16-bit word out and then change that particular bit and store the updated word in the same memory location.

Let's try to figure out how we can reach from (row, col) in the screen to memory map. Every row in our display will take `512 / 16 = 32` registers. The values for first row range from `(0, 31)`, for second row it ranges from `(32, 63)` and so on.  Let's call them row group.

A pixel in row `r` will belong in memory register group `r * 32`, now within a group it is not hard to identify that pixel at column `c` will belong to register `c / 16` (integer division). Combining these we get that the address of register in which pixel `(r, c)` lives is `32 * r + c / 16`. Now within a register the pixel will be present at location `c % 16` i.e. remainder of `c / 16`.

But we are not done yet, the screen memory mapping in our computer architecture will live inside of RAM, hence it will have some base address starting which we will have screen memory, hence to the address computed above we need to add this base address.

![[Pasted image 20250115092144.png]]

## Hack Programming: (Part 1)

#### Working with Registers and Memory

As already told we have 3 types of registers in out computer, first is `A` and `D` which are present inside of the cpu itself and other is `M` register which refers to `RAM[A]`.

Let's learn about how to work with these registers through examples.

**Example 1:** program to store value 10 in D register.
**Solution:** from the language specifications it is clear that there is not direct way to do this, but we can assign any value to register A, hence we can indirectly store 10 in D.

```
@10
D=A

// few similar operations are show below

// code to perform D++
D=D+1

// D=RAM[17]
@17
D=M

// RAM[17]=D
@17
M=D

// RAM[17] = 10
@10
D=A
@17
M=D

// RAM[5]=RAM[3]
@3
D=M
@5
M=D
```

**Example 2:** program to add values stored in `RAM[0]` and `RAM[1]` and store the result in `RAM[2]`.
**Solution:** below is the code to do so.

```
@0
D=M

@1
D=D+M

@2
M=D
```

#### How to terminate a program properly?

Let's take the example of the above program, the computer executes instructions up to line number 5, but it doesn't stop there, it keeps on increasing the program counter and execute next instructions.

But there are no next instructions in memory, well in that case the computer get's null operations which does nothing and it will keep moving ahead in the memory.

This behaviour is because computer's always do something as long as they are running. If the program is not terminated, the computer keeps moving ahead in the instruction memory.

This gives rise to a type of attack called **NOP Sled Attack** which is basically some malicious code inserted by the hacker. When the program is not terminated properly then it may reach a memory controlled by the hacker and that code might do bad things like deleting random files.

This is shown in the image below.

![[Pasted image 20250115231615.png]]

>[!Note]
>The general idea here is that we must never run an instruction that we didn't put. Even if we executed a single line of code that is not ours, the hacker might insert a jump command to a region in memory that contains malicious code.

The computer is going to do something, hence instead of it going to some area that we don't control, we might as well ask it do something that we control indefinitely. Hence, at the end of our programs we  always write code of an infinite loop.

This is show in the code below.

```
0. @0
1. D=M

2. @1
3. D=D+M

4. @2
5. M=D

// infinite loop
6. @6           // A = 6
7. 0;JMP        // goto ROM[6]
```

## Hack Programming: (Part 1)

#### Branching

Branching is a programming concept which allows us to conditionally execute certain pieces of code. Every high level programming language supports branching in some form or the other (i.e. if/else).

In machine language the only apparatus that we have that can help us implement branching is `goto` instructions.

Let's look at how we can use `goto` to implement branching using an example. We will write a function that will compute Signum of value stored in `RAM[0]`.

```
// Program: Signum.asm
// Computes: if RAM[0] > 0
//              RAM[1] = 1
//           else
//              RAM[1] = 0

0.@R0
1. D=M          // D=RAM[0]

2. @8
3. D;JGT        // goto ROM[9] if D > 0

4. @R1
5. M=0          // RAM[1]=0
6. @10          
7. 0:JMP        // jump to end of program

8. @R1
9. M=1          // RAM[1] = 1

10. @10
11. 0;JMP       // terminating the program with infinite loop
```

###### Labels
If we look at the code above without preamble and comments, it will just be a cryptic code that is very hard to understand, hence a better way to write code along with comments is to use labels.

We can use label in above code to define line numbers, so that the jump's make more sense, this is shown in the code below.

```
// Program: Signum.asm
// Computes: if RAM[0] > 0
//              RAM[1] = 1
//           else
//              RAM[1] = 0

@R0
D=M

@POSITIVE              // using the label
D;JGT

@R1
M=0
@END
0:JMP

(POSITIVE)             // declaring the label
@R1
M=1

(END)                  // declaring the label
@10
0;JMP
```

From the above code we can clearly make out which region is end of code, which is code to be executed in case `RAM[0] > 0` and which to execute is that is not the case.

These label's don't take any line number, i.e. when this code is assembled by the assembler, these label's will be replaced with the line number of instruction below it and the code will look exactly like the code without label's.

#### Variable

Let's consider a simple problem, we want a code that will swap the value of `RAM[0]` and `RAM[1]`. To write a code that does that we typically need to use a temporary place to store the value of one of the register.

In high level languages, this program will look something like this,

```
temp = R1
R1 = R2
R2 = temp
```

We can do the same thing in machine language also, we can assign some register in `RAM` the value of `RAM[0]`. But how do we decide which register to use for this purpose, well one way is to hard code the register which we want to use, but there are few problems in this approach.
- What if that memory was occupied with some other before, this, then that get's erased and make hard to debug errors.
- The code won't be very readable, if we hard code register's like that.

Hence to solve all these problems we use variables, their usage is shown in the image below.

![[Pasted image 20250116235212.png]]

At the time when this code is being assembled, the assembler will automatically find an empty location for our declared variable.

This type of code that doesn't rely on the location it is present is called **Relocatable Code**. We don't have to necessarily put it at memory `0`, but we can put it anywhere as long as we remember the base address of the location where put this.

This is enabled because we have symbolic references in our code instead of actual hard coded references.

There is generally a program called loader takes care of updating the references according to base address.
