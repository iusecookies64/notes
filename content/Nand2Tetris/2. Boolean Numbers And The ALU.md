##### Binary Addition

Addition of binary numbers is similar to how addition in decimal numbers work, we add corresponding bits and if the answer has more than one bit, then we carry the extra bit to next left bits, this is shown below.

##### Half Adders And Full Adders

Addition is a functionality that we will build inside of our hardware itself, and along with it subtraction functionality is automatically realised as x - y = x + (-y). To implement hardware that can add, we need to first be able to add two bits, this is implemented using a chip called Half Adder. It takes in two input bits that we need to add and outputs sum and carry bits. The truth table of Half adder is shown below.

#### Negative Numbers

Normally we don't just store positive numbers, rather we also need to store negative numbers and be able to do operations on them.

Hence one of the bit among k bits must be reserved to differentiate between negative and positive numbers. One way is to reserve the left most bit (most significant bit) as sign bit, if it is 0, then the number is positive and if it is one, then it is a negative number.

If we have 3 bits, then the range of numbers we can store will look at something like this.

![[Pasted image 20250104225145.png]]

As you can see that there is a problem of two zeroes in this method, also performing operations like addition and subtraction is very difficult with this method. 

##### 2's Complement Method

The way that is used to store negative number is to store them as 2's complement of their positive counter part i.e. In a k bit system -x will be stored as 2^k - x. In this system with 3 bits, the numbers look something like this.

![[Pasted image 20250104230130.png]]

##### How to compute 2's complement

In a k bit system, to get -x we need to do 2^k - x, but 2^k cannot be represented in a k bit system.

Another way to compute 2's complement of a number is using the fact that `x + not(x) = 2^k-1` which gives `not(x)+1 = 2^k - x`. Hence to get compute 2's complement of x we first invert all bits of x (i.e. not(x)) and then add one two the result.

The biggest benefit of using 2's complement is that it automatically makes addition of positive and negative numbers correct automatically. Consider the subtraction x - y, in our system, this will be occurring as follows.

## The ALU

The Arithmetic and Logical unit is a chip present in the cpu of a computer and that can perform a bunch of arithmetic operations (Addition, multiplication, division, ...) and logical operations (And, Or, Xor, ...) on the input values.

What all operations the ALU supports depends on the person designing the ALU. The features that we decide not to put in the ALU are then needed to be implemented in the software layer.

In this project we have to build the following, chips Half Adder, Full Adder, Add16, Inc16 and ALU.
##### Half Adder

Below is the hdl code for half adder.

```
/**
* Computes the sum of two bits.
*/

CHIP HalfAdder {
	IN a, b; // 1-bit inputs
	OUT sum, // Right bit of a + b
	carry; // Left bit of a + b

	PARTS:
	Xor(a = a, b = b, out = sum);
	And(a= a, b=b , out=carry );
}
```

##### Full Adder

Below is the hdl code for Full Adder.

```
/**
* Computes the sum of three bits.
*/

CHIP FullAdder {
	IN a, b, c; // 1-bit inputs
	OUT sum, // Right bit of a + b + c
	carry; // Left bit of a + b + c
	
	PARTS:
	HalfAdder(a=a, b=b, sum=sum1, carry=carry1);
	HalfAdder(a=sum1, b=c, sum=sum, carry=carry2);
	Or(a=carry1, b=carry2, out=carry);
}
```

##### Add16

Below is the hdl for Add16 chip.

```hdl
/**
* 16-bit adder: Adds two 16-bit two's complement values.
* The most significant carry bit is ignored.
*/

CHIP Add16 {
	IN a[16], b[16];
	OUT out[16];
	
	PARTS:
	HalfAdder(a= a[0], b= b[0], sum=out[0] , carry=carry1);
	FullAdder(a= a[1], b= b[1], sum=out[1] , c=carry1, carry=carry2);
	FullAdder(a= a[2], b= b[2], sum=out[2] , c=carry2, carry=carry3);
```

##### Inc16

Below is the hdl for Inc16 chip.

```hdl
/**
* 16-bit incrementer:
* out = in + 1
*/

CHIP Inc16 {
	IN in[16];
	OUT out[16];
	
	PARTS:
	Add16(a = in, b[0] = true, out = out);
}
```

##### ALU

Below is the hdl for ALU.

```hdl
/**
* ALU (Arithmetic Logic Unit):
* Computes out = one of the following functions:
* 0, 1, -1,
* x, y, !x, !y, -x, -y,
* x + 1, y + 1, x - 1, y - 1,
* x + y, x - y, y - x,
* x & y, x | y
* on the 16-bit inputs x, y,
* according to the input bits zx, nx, zy, ny, f, no.
* In addition, computes the two output bits:
* if (out == 0) zr = 1, else zr = 0
* if (out < 0) ng = 1, else ng = 0
*/

// Implementation: Manipulates the x and y inputs
// and operates on the resulting values, as follows:
// if (zx == 1) sets x = 0 // 16-bit constant
// if (nx == 1) sets x = !x // bitwise not
// if (zy == 1) sets y = 0 // 16-bit constant
// if (ny == 1) sets y = !y // bitwise not
// if (f == 1) sets out = x + y // integer 2's complement addition
// if (f == 0) sets out = x & y // bitwise and
// if (no == 1) sets out = !out // bitwise not

CHIP ALU {
	IN
		x[16], y[16], // 16-bit inputs
		zx, // zero the x input?
		nx, // negate the x input?
		zy, // zero the y input?
		ny, // negate the y input?
		f, // compute (out = x + y) or (out = x & y)?
		no; // negate the out output?
	OUT
		out[16], // 16-bit output
		zr, // if (out == 0) equals 1, else 0
		ng; // if (out < 0) equals 1, else 0
	
	PARTS:
	Mux16(a=x, b=false, sel=zx, out=x1);
	Not16(in=x1, out=nx1);
	Mux16(a=x1, b=nx1, sel=nx, out=x2);
	Mux16(a=y, b=false, sel=zy, out=y1);
	Not16(in=y1, out=ny1);
	Mux16(a=y1, b=ny1, sel=ny, out=y2);
	Add16(a=x2, b=y2, out=xPlusy);
	And16(a=x2, b=y2, out=xAndy);
	Mux16(a=xAndy, b=xPlusy, sel=f, out=res1);
	Not16(in=res1, out=notres1);
	Mux16(
		a=res1,
		b=notres1,
		sel=no,
		out=out,
		out[0..7]=temp,
		out[8..15]=temp2,
		out[15]=ng
	);
	Or8Way(in=temp, out=zr1);
	Or8Way(in=temp2, out=zr2);
	Or(a=zr1, b=zr2, out=zr3);
	Not(in=zr3, out=zr);
}
```
