## 1. The Foundations of Text Vectorization

### The Fundamental Bridge: From Symbols to Vectors

Machine learning algorithms and statistical models are mathematical optimization engines that operate strictly on numerical data (matrices, tensors, and continuous vectors). They cannot interpret raw string characters or linguistic syntax directly.

```
                                  Text Vectorization Pipeline
┌────────────────────────┐         ┌────────────────────────┐         ┌────────────────────────┐
│    Raw Text Corpus     │  ─────► │     Vectorization      │  ─────► │    Numerical Matrix    │
│ "I love NLP and AI..." │         │ (OHE / BoW / TF-IDF)   │         │  [[0, 1, 1, 0, ...],   │
└────────────────────────┘         └────────────────────────┘         │   [1, 0, 1, 0, ...]]   │
                                                                      └───────────┬────────────┘
                                                                                  │
                                                                                  ▼
                                                                      ┌────────────────────────┐
                                                                      │   Statistical Model    │
                                                                      │   (Classifier/ML Engine)│
                                                                      └────────────────────────┘
```

Historically, computational linguistics relied on deterministic, rule-based systems—such as regular expressions, morphological stemmers (e.g., Porter Stemmer), and lemmatizers. While these tools normalize surface forms of words, they do not provide mathematical representations suitable for statistical machine learning.

**Vectorization** (also referred to broadly as creating **word embeddings** or **feature extraction**) is the deterministic or statistical transformation of discrete linguistic units (characters, words, sentences, documents) into numerical vectors in a continuous or discrete vector space.

## 2. One-Hot Encoding (OHE)

One-Hot Encoding represents words as standard basis vectors in a high-dimensional Euclidean space $\mathbb{R}^{\vert{}V\vert{}}$, where $\vert{}V\vert{}$ denotes the total size of the unique vocabulary.

Every unique word $w_i \in V$ is assigned a unique index $i \in \{1, 2, \dots, \vert{}V\vert{}\}$. The one-hot vector $\mathbf{e}_i$ is defined as a vector where the $i$-th entry is $1$ and all other entries are $0$:

$$\mathbf{e}_i = [\underbrace{0, \dots, 0}_{i-1 \text{ zeros}}, 1, \underbrace{0, \dots, 0}_{\vert{}V\vert{}-i \text{ zeros}}]^T \in \{0, 1\}^{\vert{}V\vert{}}$$

```
Vocabulary V = {"AI", "future", "I", "is", "love", "NLP"}  (|V| = 6)

Vector Representations:
"AI"     ──► [ 1,  0,  0,  0,  0,  0 ]
"future" ──► [ 0,  1,  0,  0,  0,  0 ]
"I"      ──► [ 0,  0,  1,  0,  0,  0 ]
"is"     ──► [ 0,  0,  0,  1,  0,  0 ]
"love"   ──► [ 0,  0,  0,  0,  1,  0 ]
"NLP"    ──► [ 0,  0,  0,  0,  0,  1 ]
```

When applied at the sentence level without term counts, a document vector is constructed as the logical binary union (indicator vector) across its constituent word vectors:

$$\mathbf{d}_{\text{OHE}} = \bigvee_{w \in d} \mathbf{e}_w$$

### Step-by-Step Construction and Implementation

```python
import pandas as pd

# Sample Corpus
documents = [
    "I love NLP",
    "I love AI",
    "NLP is future"
]

# Step 1: Extract and sort unique vocabulary (|V|)
all_words = " ".join(documents).split()
vocab = sorted(list(set(all_words)))
print("Vocabulary:", vocab)
# Output: ['AI', 'I', 'NLP', 'future', 'is', 'love']

# Step 2: Generate One-Hot Encoded Document Vectors
one_hot_matrix = []
for doc in documents:
    tokens = doc.split()
    # Initialize zero vector of size |V|
    vector = [0] * len(vocab)
    for idx, word in enumerate(vocab):
        if word in tokens:
            vector[idx] = 1
    one_hot_matrix.append(vector)

# Display as DataFrame
df_ohe = pd.DataFrame(one_hot_matrix, index=documents, columns=vocab)
print(df_ohe)
```

**Resulting Output Matrix:**

| **Document**        | **AI** | **I** | **NLP** | **future** | **is** | **love** |
| ------------------- | ------ | ----- | ------- | ---------- | ------ | -------- |
| **"I love NLP"**    | $0$    | $1$   | $1$     | $0$        | $0$    | $1$      |
| **"I love AI"**     | $1$    | $1$   | $0$     | $0$        | $0$    | $1$      |
| **"NLP is future"** | $0$    | $0$   | $1$     | $1$        | $1$    | $0$      |

### Structural Limitations of One-Hot Encoding

- **The Orthogonality Problem (Zero Semantic Retention):** By mathematical construction, standard basis vectors are mutually orthogonal. For any two distinct words $w_i$ and $w_j$ ($i \neq j$), their dot product and cosine similarity evaluate to zero:
    $$\mathbf{e}_i \cdot \mathbf{e}_j = 0 \implies \cos(\theta) = \frac{\mathbf{e}_i \cdot \mathbf{e}_j}{\Vert{}\mathbf{e}_i\Vert{} \Vert{}\mathbf{e}_j\Vert{}} = 0$$
    
    Consequently, semantically related words (e.g., _dog_ and _puppy_) share the exact same geometric distance as completely unrelated words (e.g., _dog_ and _refrigerator_). The vector space carries no concept of semantic similarity.
    
- **Extreme Sparsity and Memory Inefficiency:** If a realistic corpus has a vocabulary of $\vert{}V\vert{} = 50,000$, every single word is represented by a $50,000$-dimensional vector containing $49,999$ zeros and a single $1$. Storing and computing operations over these vectors wastes memory and compute cycles.
    
- **Variable Length and Sequence Loss:** One-Hot document vectors lose word order and require fixed-length padding strategies when fed into fixed-size neural architectures.

## 3. Bag of Words (BoW / Count Vectorization)

### First-Principles Formulation

The **Bag of Words (BoW)** model extends One-Hot Encoding by shifting from binary presence to **term multiplicity** (frequency counts).

Under the BoW paradigm:

1. A document is treated as an unordered multiset ("bag") of words.
    
2. Grammatical syntax, sentence structure, and sequential token ordering are discarded.
    
3. Word frequency within the document is preserved.

```
Input Document: "The cat sat on the mat"

Step 1: Discard Syntax & Word Order
Step 2: Aggregate Frequencies
        ┌──────────────┐
        │  the: 2      │
        │  cat: 1      │
        │  sat: 1      │
        │  on:  1      │
        │  mat: 1      │
        └──────────────┘
```

For a corpus $D$ with vocabulary $V = \{w_1, w_2, \dots, w_{\vert{}V\vert{}}\}$, a document $d \in D$ is represented as a vector $\mathbf{x}_d \in \mathbb{N}^{\vert{}V\vert{}}$:

$$\mathbf{x}_d = [f(w_1, d), f(w_2, d), \dots, f(w_{\vert{}V\vert{}}, d)]$$

where $f(w, d)$ is the frequency of word $w$ occurring in document $d$.

### Python Implementation (`scikit-learn`)

```python
import pandas as pd
from sklearn.feature_extraction.text import CountVectorizer

# Corpus definition
corpus = [
    "The cat sat on the mat.",
    "The dog sat on the log.",
    "Cats and dogs are enemies."
]

# Initialize CountVectorizer (handles tokenization, lowercasing, punctuation stripping)
vectorizer = CountVectorizer()

# Fit vocabulary and transform corpus to Document-Term Matrix (DTM)
X_bow = vectorizer.fit_transform(corpus)

# The output X_bow is a SciPy Compressed Sparse Row (CSR) matrix
print(f"Matrix Type: {type(X_bow)}")
print(f"Matrix Shape: {X_bow.shape}") # (3 documents, 12 unique vocabulary features)

# Convert CSR sparse matrix to dense DataFrame for visualization
df_bow = pd.DataFrame(X_bow.toarray(), index=corpus, columns=vectorizer.get_feature_names_out())
print(df_bow)
```

**Output Document-Term Matrix:**

|**Document**|**and**|**are**|**cat**|**cats**|**dog**|**dogs**|**enemies**|**log**|**mat**|**on**|**sat**|**the**|
|---|---|---|---|---|---|---|---|---|---|---|---|---|
|**"The cat sat on the mat."**|$0$|$0$|$1$|$0$|$0$|$0$|$0$|$0$|$1$|$1$|$1$|$2$|
|**"The dog sat on the log."**|$0$|$0$|$0$|$0$|$1$|$0$|$0$|$1$|$0$|$1$|$1$|$2$|
|**"Cats and dogs are enemies."**|$1$|$1$|$0$|$1$|$0$|$1$|$1$|$0$|$0$|$0$|$0$|$0$|

### Storage Mechanics: The Compressed Sparse Row (CSR) Matrix

Because typical Document-Term matrices are populated predominantly by zeros (often $>99\%$ sparse), storing them as dense 2D arrays wastes memory. `scikit-learn` outputs a **Compressed Sparse Row (CSR)** matrix by default.

A CSR matrix compresses sparse data using three 1D arrays:

1. `data`: Non-zero values stored sequentially.
    
2. `indices`: Column indices corresponding to each non-zero element.
    
3. `indptr`: Pointers to where each matrix row begins and ends in `data`.

$$\text{Memory Overhead: } \mathcal{O}(\text{Non-Zero Elements}) \ll \mathcal{O}(M \times \vert{}V\vert{})$$

### Advantages and Limitations of Bag of Words

- **Advantages:**
    - Highly efficient and simple to compute.
        
    - Effective for keyword-dense text classification tasks where word presence correlates with labels (e.g., spam detection identifying triggers like _lottery_, _winner_, _free_, _urgent_).
    
- **Limitations:**
    - **Permutation Invariance (Loss of Syntax & Context):** Because word order is discarded, sentences with opposite meanings produce identical vectors:
 $$\text{vec("The dog bit the man")} \equiv \text{vec("The man bit the dog")}$$
     - **High Dimensionality & Sparsity:** Vocabulary size grows linearly with unique corpus tokens, leading to sparse feature spaces that require regularization.
         
    - **Dominance of High-Frequency Words:** Common functional tokens (_the_, _is_, _and_) receive the largest integer counts despite offering little topical discrimination.

## 4. $N$-Gram Language Representations

To mitigate the complete loss of local context in unigram Bag of Words models, **$N$-grams** capture contiguous sequences of $n$ items from a given sample of text.

- **Unigram ($n=1$):** Single isolated tokens (`["machine", "learning", "is", "great"]`).
    
- **Bigram ($n=2$):** Two-token sliding window (`["machine learning", "learning is", "is great"]`).
    
- **Trigram ($n=3$):** Three-token sliding window (`["machine learning is", "learning is great"]`).

```
Sentence: "The food was not good"

Unigrams: ["The", "food", "was", "not", "good"]
--> Loses the direct dependency between "not" and "good".

Bigrams:  ["The food", "food was", "was not", "not good"]
--> Retains local negation ("not good").
```

### Implementation with Range Bounds

```python
from sklearn.feature_extraction.text import CountVectorizer

sample = ["The food was not good at all."]

# Extract both unigrams and bigrams
ngram_vec = CountVectorizer(ngram_range=(1, 2))
X_ngram = ngram_vec.fit_transform(sample)

print(ngram_vec.get_feature_names_out())
# Output contains: 'all', 'at', 'at all', 'food', 'food was', 'good', 'good at', 
#                  'not', 'not good', 'the', 'the food', 'was', 'was not'
```

### The Combinatorial Explosion Problem

While $N$-grams capture localized syntax and handle negation, expanding the $n$-gram window size triggers exponential growth in vocabulary size:

$$\vert{}V_{n\text{-gram}}\vert{} \approx \mathcal{O}(\vert{}V\vert{}^n)$$

As $n$ increases:

1. Feature space dimensionality increases rapidly.
    
2. The Document-Term matrix becomes sparser.
    
3. Out-of-vocabulary (OOV) rates on unseen test text increase because exact multi-word sequences repeat far less frequently than single words.

## 5. Term Frequency-Inverse Document Frequency (TF-IDF)

### The First-Principles Intuition

In Bag of Words, term frequency rewards words that appear frequently. However, in human language, the most frequent words across a corpus are typically grammatical function words (e.g., _the_, _is_, _in_) that carry minimal topical information. Conversely, domain-defining words (e.g., _photosynthesis_, _mitochondria_, _hyperplane_) appear frequently within specific documents, but rarely across the general corpus.

**TF-IDF** balances these dynamics by combining two metrics:

1. **Term Frequency ($\text{TF}$):** How frequently a term appears within a target document (local importance).
    
2. **Inverse Document Frequency ($\text{IDF}$):** How rarely the term appears across the entire corpus of documents (global specificity).

```
  ┌────────────────────────────────────────────────────────┐
  │                 TF-IDF Weighting Logic                 │
  │                                                        │
  │   High TF  (Frequent in this document)                 │
  │     ×                                   ══► HIGH SCORE │
  │   High IDF (Rare across other documents)               │
  │                                                        │
  │   High TF  (Frequent in this document)                 │
  │     ×                                   ══► LOW SCORE  │
  │   Low IDF  (Common across all documents)               │
  └────────────────────────────────────────────────────────┘
```

### Mathematical Formulations

#### 1. Standard Textbook Formulation

For a term $t$ in a document $d$ within a corpus $D$ of total size $N = \vert{}D\vert{}$:
$$\text{TF}(t, d) = \frac{f(t, d)}{\sum_{t' \in d} f(t', d)} \quad \text{or raw count } f(t, d)$$
$$\text{IDF}(t, D) = \log \left( \frac{N}{\text{DF}(t)} \right)$$
where $\text{DF}(t)$ is the **Document Frequency** (the count of documents containing term $t$).
$$\text{TF-IDF}(t, d, D) = \text{TF}(t, d) \times \text{IDF}(t, D)$$
- If a word appears in every document ($\text{DF}(t) = N$), then $\text{IDF} = \log(1) = 0$, driving the total TF-IDF score to zero.
     
- If a word is rare across the corpus ($\text{DF}(t) \ll N$), $\text{IDF}$ is a large positive number, scaling up the importance of that word.
 
#### 2. The `scikit-learn` Implementation (Smoothed & Normalized)

To avoid division-by-zero errors when a word is absent from the training set, `scikit-learn` applies an additive smoothing parameter of $1$ and adds a constant $1$ to the final logarithm:
$$\text{IDF}_{\text{sklearn}}(t, D) = \ln \left( \frac{1 + N}{1 + \text{DF}(t)} \right) + 1$$
To ensure that longer documents with higher word counts do not dominate shorter documents, the resulting vector $\mathbf{v}$ is normalized to unit length via Euclidean ($L_2$) normalization:
$$\mathbf{v}_{\text{norm}} = \frac{\mathbf{v}}{\Vert{}\mathbf{v}\Vert{}_2} = \frac{\mathbf{v}}{\sqrt{\sum_i v_i^2}}$$
### Python Implementation (`scikit-learn`)

```python
import pandas as pd
from sklearn.feature_extraction.text import TfidfVectorizer

# Sample Corpus
corpus = [
    "The car is fast",
    "The race car is fast",
    "The car is parked"
]

# Initialize TF-IDF Vectorizer
tfidf_vec = TfidfVectorizer()

# Compute TF-IDF matrix
X_tfidf = tfidf_vec.fit_transform(corpus)

# Inspect dense DataFrame
df_tfidf = pd.DataFrame(
    X_tfidf.toarray(), 
    index=corpus, 
    columns=tfidf_vec.get_feature_names_out()
)
print(df_tfidf.round(3))
```

**Resulting TF-IDF Matrix:**

|**Document**|**car**|**fast**|**is**|**parked**|**race**|**the**|
|---|---|---|---|---|---|---|
|**"The car is fast"**|$0.464$|$0.610$|$0.464$|$0.000$|$0.000$|$0.464$|
|**"The race car is fast"**|$0.363$|$0.477$|$0.363$|$0.000$|$0.627$|$0.363$|
|**"The car is parked"**|$0.413$|$0.000$|$0.413$|$0.713$|$0.000$|$0.413$|

**Key Mathematical Insights:**

- **Corpus Stopwords Suppressed:** Common words across all 3 documents (_the_, _is_, _car_) receive lower weights ($0.36 - 0.46$).
    
- **Distinctive Content Rewarded:** The word _race_ appears in only 1 document, earning a high weight of $0.627$. Similarly, _parked_ receives $0.713$.
    
- **Document Length Dynamics:** Even though _car_ appears once in both Document 1 and Document 2, its weight drops from $0.464$ to $0.363$ in Document 2 due to the presence of _race_ and subsequent $L_2$ normalization.

### Advantages and Limitations of TF-IDF

- **Advantages:**
      
    - **Automated Noise Suppression:** Suppresses high-frequency stopwords without requiring hand-curated exclusion lists.
        
    - **Domain-Specific Salience:** Highlights specialized terminology (e.g., _mitochondria_, _jurisprudence_) based on statistical distribution.
        
    - **Computationally Lightweight:** Fast to compute across millions of documents.
        
- **Limitations:**
      
    - **No Semantic Generalization:** Models cannot recognize synonyms (_automobile_ vs. _car_) or polysemous meanings (a financial _bank_ vs. a river _bank_).
        
    - **Sparse High Dimensionality:** Retains the dimensional scaling issues of Bag of Words as vocabulary grows.
        
    - **Loss of Global Grammar:** Disregards sentence structure, sequence dynamics, and multi-clause dependencies.

## 6. Systematic Comparison of Traditional Vectorization Models

|**Dimension**|**One-Hot Encoding (OHE) MD**|**Bag of Words (BoW) MD**|**N-Grams Model MD**|**TF-IDF Vectorization MD**|
|---|---|---|---|---|
|**Primary Unit**|Isolated single tokens|Document-level tokens|Contiguous token sequences of length $n$|Document-level tokens (or $N$-grams)|
|**Vector Values**|Binary: $\{0, 1\}$|Integer counts: $\mathbb{N}_0$|Integer counts or presence|Real values: $\mathbb{R}^+$ ($L_2$ bounded)|
|**Local Word Order**|Discarded entirely|Discarded entirely|Preserved within $n$-word window|Discarded entirely|
|**Dimensionality**|$\vert{}V\vert{}$ (Vocabulary size)|$\vert{}V\vert{}$ (Vocabulary size)|$\approx \mathcal{O}(\vert{}V\vert{}^n)$ (High explosion)|$\vert{}V\vert{}$ (Vocabulary size)|
|**Stopword Handling**|Unhandled (equal weight)|Distorted (dominated by counts)|Captured in phrases (e.g., "is not")|Automatically downweighted by $\text{IDF}$|
|**Geometric Metric**|All vectors orthogonal ($\theta = 90^\circ$)|Dot products reflect common word counts|Dot products reflect common phrase counts|Cosine similarity captures lexical sharing|
|**Typical Use Cases**|Categorical variables, small lexicons|Spam filtering, basic classification|Sentiment analysis with negation|Information retrieval, search engines, baseline classifiers|
