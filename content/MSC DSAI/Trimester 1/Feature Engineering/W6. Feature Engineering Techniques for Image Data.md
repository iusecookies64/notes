## Feature Engineering for Image Data: Module Introduction

This module explores how to transform raw pixel data into meaningful representations that machine learning models can understand.

---

### 1. Challenges of Image Data

Unlike structured tabular data, image data presents unique hurdles:

* **Spatial Relationships:** Pixels are not independent. Their meaning is derived from their neighbors; shuffling pixels destroys the context (edges, textures, shapes).
* **High Dimensionality:** A single color image contains millions of values (). This leads to slow training and **overfitting**.
* **Environmental Variation:** Models must account for changes in scale, rotation, lighting, and background noise.

### 2. The Role of Feature Engineering

The goal is to reduce complexity by extracting **low-dimensional representations** of visual patterns. While deep learning (CNNs) automates this, manual feature engineering remains vital for:

* Classical machine learning methods.
* Small datasets where deep learning might overfit.
* Hybrid systems and real-time applications.

---

### 3. Key Techniques Covered

The module focuses on three primary methods to capture discriminative features:

| Technique | Description | Use Case |
| --- | --- | --- |
| **Edge Detection (Canny)** | Highlights boundaries where there are sharp changes in intensity. | Identifying shapes and outlines. |
| **Corner Detection (Harris)** | Identifies points where edges meet. | Object tracking and image matching. |
| **HOG (Histogram of Oriented Gradients)** | Summarizes local gradient directions. | Describing object shapes (e.g., pedestrian detection). |

**Other Noteworthy Methods:**

* **Thresholding:** Converts grayscale images to binary (black and white) to separate foreground from background.
* **Texture Descriptors:** Captures patterns like roughness or repeating structures.
* **SIFT (Scale-Invariant Feature Transform):** Robust features that remain consistent despite changes in scale or rotation.

---

### 4. Tools & Libraries

We will implement these techniques using two industry-standard Python libraries:

* **OpenCV:** A powerful, real-time library used for computer vision, video analysis, and object detection.
* **Scikit-Image (skimage):** Built on NumPy and SciPy; ideal for scientific research, filtering, and image segmentation.

## Feature Engineering: Canny Edge Detection

Edge detection is the process of identifying discontinuities in pixel intensity (sharp changes from light to dark or vice versa). While basic methods use **gradients** (rate of change) calculated via kernels/filters, the **Canny Edge Detector** is considered the gold standard because it is a multi-step process designed to produce clean, thin, and connected edges.

---

### 1. The 5 Stages of Canny Edge Detection

After converting an image to grayscale, the algorithm follows these steps:

1. **Noise Reduction:** Uses a **Gaussian filter** to smooth the image. This prevents the algorithm from mistaking random pixel noise for actual edges.
2. **Gradient Calculation:** Calculates the intensity gradients and directions using operators like **Sobel kernels**. This identifies where the sharpest changes in brightness occur.
3. **Non-Maximum Suppression:** A "thinning" technique. The algorithm looks at each pixel and checks if it is the local maximum in the direction of the gradient. If it isn't, it's suppressed (set to zero).
4. **Double Thresholding:** Categorizes remaining pixels into three groups based on intensity:
* **Strong Edges:** Above the High Threshold.
* **Weak Edges:** Between the Low and High Thresholds.
* **Non-Edges:** Below the Low Threshold (discarded).


5. **Hysteresis Thresholding:** The final cleanup. It keeps a "weak edge" only if it is connected to a "strong edge." Unconnected weak edges are discarded as noise.

---

### 2. Implementation with OpenCV

In practice, you don't need to code these five steps manually. The `cv2` (OpenCV) library handles the complexity with a single function.

**Key Pre-processing Steps:**

* **Normalization:** Scaling pixel values (0–255) to a range of 0–1 by dividing by 255. This helps with model convergence.
* **Flattening:** Converting a 2D image (e.g., ) into a 1D vector () for traditional machine learning models like Logistic Regression.

**The OpenCV Function:**

```python
# Conceptual usage within a function
edges = cv2.Canny(image, threshold1, threshold2)

```

* `threshold1`: The **low** threshold for hysteresis.
* `threshold2`: The **high** threshold for identifying strong edges.

## Feature Engineering: Corner Detection

Corners are points where edges intersect, representing a two-dimensional change in pixel intensity (variation in both  and  directions). They are more distinctive than edges, making them essential for object tracking, image stitching, and 3D reconstruction.

---

### 1. Harris Corner Detection

The Harris detector uses a sliding window to measure intensity changes.

* **Flat region:** Small change in all directions.
* **Edge:** Large change in one direction ( or ).
* **Corner:** Large change in **all** directions.

**The 5-Step Process:**

1. **Gradient Calculation:** Finds intensity changes in  and .
2. **Structure Tensor:** Summarizes gradient products in a local window.
3. **Corner Response ():** Calculates a score for each pixel.
4. **Thresholding:** Filters out pixels with low scores.
5. **Non-Maximum Suppression:** Refines the detected points into precise corner locations.

**Primary Function (OpenCV):**

```python
import cv2
import numpy as np

# Image must be float32
gray_float = np.float32(image)
# blockSize: neighborhood size; ksize: Sobel kernel size; k: Harris detector free parameter
dst = cv2.cornerHarris(gray_float, blockSize=2, ksize=3, k=0.04)

```

---

### 2. Shi-Tomasi Corner Detection

Shi-Tomasi is an optimization of the Harris method. While Harris uses a complex response formula, Shi-Tomasi simply calculates the **minimum eigenvalue** of the structure tensor. If the minimum eigenvalue is above a certain threshold, the point is considered a corner. This method is generally more stable and reliable than Harris.

**Key Parameters:**

* **Max Corners:** Limits the number of corners returned.
* **Quality Level:** A value between 0–1 representing the minimum quality of corners (relative to the best corner).
* **Min Distance:** The minimum Euclidean distance between detected corners to avoid clustering.

**Primary Function (OpenCV):**

```python
import cv2

# image: 8-bit or floating-point 32-bit, single-channel
corners = cv2.goodFeaturesToTrack(image, maxCorners=40, qualityLevel=0.01, minDistance=10)

```

---

### Comparison: Harris vs. Shi-Tomasi

| Feature | Harris Corner Detection | Shi-Tomasi Corner Detection |
| --- | --- | --- |
| **Scoring Logic** | Complex response function () | Minimum eigenvalue (simpler) |
| **Stability** | Sensitive to tunable parameters | More stable and repeatable |
| **OpenCV Function** | `cv2.cornerHarris()` | `cv2.goodFeaturesToTrack()` |
| **Data Requirement** | Requires `float32` input | Works with `uint8` or `float32` |

## Feature Engineering: Histogram of Oriented Gradients (HOG)

**HOG** is a classic feature descriptor that characterizes local object appearance and shape by the distribution of intensity gradients (edge directions). It is historically famous for its success in **pedestrian detection** because it focuses on outlines rather than pixel-perfect colors or textures.

---

### 1. How HOG Works: The 4-Step Process

HOG converts the visual intuition of shapes into a structured mathematical vector:

1. **Gradient Computation:** The algorithm calculates the intensity changes in the image. This identifies where edges are and how sharp they are.
2. **Orientation Binning:** The image is divided into small regions called **cells** (e.g.,  pixels). For each cell, a histogram is created where pixels "vote" for an orientation bin (e.g., 0°, 20°, 40°) based on their gradient angle. The "strength" of the vote is determined by the gradient magnitude.
3. **Block Normalization:** Cells are grouped into larger **blocks**. The histograms within these blocks are normalized to account for lighting changes, shadows, and contrast variations.
4. **Feature Vector Construction:** All normalized histograms from across the image are concatenated into a single, long **feature vector** that represents the entire shape.

---

### 2. Implementation with Scikit-Image

Unlike the previous techniques which used OpenCV, HOG is commonly implemented using the `skimage` library.

**Primary Function (Scikit-Image):**

```python
from skimage.feature import hog

# orientations: number of bins in the histogram
# pixels_per_cell: size of the local region
# cells_per_block: size of the normalization area
# visualize: returns an image representation of the HOG
fd, hog_image = hog(image, 
                    orientations=9, 
                    pixels_per_cell=(8, 8), 
                    cells_per_block=(2, 2), 
                    visualize=True)

```

---

### 3. Why Use HOG?

* **Robustness:** It is resistant to small shifts (translations) and rotations.
* **Invariance:** Block normalization makes it effective even under uneven lighting or shadows.
* **Shape-Focused:** It ignores irrelevant details like color, focusing purely on the structural geometry of the object.

## Putting It All Together: From Features to Classification

This final section demonstrates the practical value of feature engineering. By comparing **Raw Pixels** to **Engineered Features (HOG)**, we can see a measurable improvement in how machine learning models perform.

---

### 1. The Experiment: Raw Pixels vs. HOG

To evaluate the impact of feature engineering, a Logistic Regression classifier was trained on the MNIST dataset using two different approaches:

| Feature Source | Input Description | Accuracy | Key Observation |
| --- | --- | --- | --- |
| **Raw Pixels** | Flattened  (784 features) intensity values. | **~91.85%** | High baseline, but sensitive to noise and lighting. |
| **HOG Features** | Structured vector of local edge orientations. | **~93.80%** | **Improved accuracy.** Captures essential shapes, making it more robust. |

---

### 2. Implementation Workflow

The process of using engineered features for training follows these steps:

1. **Feature Extraction:** Run the algorithm (Canny, Harris, or HOG) on the raw images.
2. **Vectorization:** Convert the results into a 2D array (Feature Matrix) that the model can accept.
3. **Data Split:** Divide the features into **Training (80%)** and **Testing (20%)** sets.
4. **Training:** Fit the classifier (e.g., Logistic Regression) using the feature vectors.
5. **Evaluation:** Compare performance metrics like **Accuracy** and **F1-Score**.

**Primary Function (Model Training):**

```python
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import train_test_split

# Splitting engineered HOG features
X_train, X_test, y_train, y_test = train_test_split(X_hog, y_hog, test_size=0.2)

# Training the model
clf = LogisticRegression(max_iter=1000)
clf.fit(X_train, y_train)

```
