co### Assembly Languages And Assemblers

In the last chapter we were focused on the right side of the below process, i.e. the machine language, the chapter before last chapter we were focused on the left side of the process i.e. the assembly language. 

In this chapter we are going to look at the centre of this process, which is the assembler i.e. the software which converts a file containing assembly code to machine code.

![[output 1.png]]

The **"Assembler"** is a software, and in almost all cases it is the first software layer above the hardware. There is much more software above it, but all of it depends on this.

So far we have only built a computer which can run machine code, hence it means if we want to translate an assembly code to machine code on our computer, then we need to write our assembler also in machine code.

But, writing assembler in machine code would be very difficult, hence for now, we will think our computer as not the first computer in the world i.e. there are other computers like the device that you are reading this from that exist in this world and we can write our assembler on it.

Hence, we will write assembler in a high level programming language on another computer. Then when we need to run an assembly code on our computer, we will first assemble it to machine code using the assembler on other computer and then run the translated machine code in our computer.

This is called **Cross Compiler** (A cross compiler is a compiler capable of creating executable code for a platform other than the one on which the compiler is running). This is most popular in case of embedded systems, where you develop the software for it in another more powerful machine.

>[!Note]
>In a modern computer, the assembler is **self-hosted** i.e. the assembler lives on the hardware for which is assembles the assembly code. 
>
>This assembler needs to be in machine language otherwise it is of no use, and writing an assembler in machine code is very tedious and error-prone. Below are the steps that are followed to write a self-hosted assembler. 
>- First a very bare bone simple (often inefficient) assembler is written directly in machine language.
>- Then using this assembler a more sophisticated assembler is written and converted to machine code. 
>- Then using this an even more advanced assembler is written using this assembler and so on the process continuous until we have a very powerful assembler.
>
>This bootstrapping using a simpler version is also used when developing compilers for different platforms i.e. first a simple compiler will be written, then using it a more sophisticated compiler will be written and so on.
#### Basic Assembler Logic

In a assembler, the following logic repeats until end-of-file is reached,

- Read the next Assembly Language command. This is usually the next line in the file which is not empty or comment.

![[output 2.png]]

- Break it into the different fields it is composed of, this usually requires some string manipulation to get different parts of the instruction.

![[Pasted image 20250215172713.png]]

- Lookup the binary code for each field, this is provided by the language specification.
- Combine these codes into a single machine language command, some times we have to pad the instructions before combining so that it matches the language specification.
- Output this machine language command
#### Symbols

One more feature that is present in almost all assembly languages is **Symbols**. Symbols are,
- **Labels** given to some part of the assembly code.
- **Variables** that stores some value which can be referred by the variable name rather than hard coding the address.

Our assembler must replace these symbols with respective addresses. We have to maintain a lookup table where we will store for each symbol it's respective address.
#### Variables

There's only one way we can use variable in hack assembly language, and that is in an A-Instruction as shown below.

```
// code to store 10 in a variable
@10
D=A
@var
M=D        // RAM[var] = 10
```

When we see a variable, we look in the lookup table whether it is already present or not, if it is present the we simply use its address.

If it is not present, the it is the first time we are seeing it, hence we need to find an empty address in ram which we can assign to the given variable and store this in lookup table.

![[Pasted image 20250215180831.png]]
#### Labels

In case of labels, its a little bit tricky. If we see a label declaration, then we add into lookup table for this label the address of the instruction below it.

```
(LOOP)
// some code

JMP LOOP
```

Then when wee see this label used, then we gets the instruction address from the lookup table and replace the label with the address.

**Forward References:** but what happens when we reference a label before its declaration i.e. code is trying to jump to a later instruction that is not seen yet (and don't know where it might be). There two solutions to this problem,
- First is to leave this as blank until label appears, then fill the blanks.
- The second approach is to process the code in 2 passes, in first pass figure out all the addresses, and in the next pass we will already have the addresses in the lookup table and there will no issue of forward reference.

### Hack Language Specifications

Before getting into the details of the translation process, lets briefly take a look at the hack language specifications again.

There are mainly 4 things in the hack assembly language as shown below,
- First is the A-Instruction, which store a value in the a register, we can directly put a value or use a symbol.

![[Pasted image 20250215190606.png]]

- The next type of instruction is the C-Instruction, which can perform computation, assign its output to ADM registers and jump to some part of the code.

![[Pasted image 20250215190831.png]]

- Next is symbols, we can use some predefined symbols and then also create symbols of our own (labels and variables).

![[Pasted image 20250215191040.png]]

- Next there are comments, white spaces and indentations which are ignored by the assembler and is used to better format the code and make explain code using comments.

### Assembly Process: Handling Instructions

We will first write a basic assembler which only translates assembly language without any symbols, we will look at how to handle symbols later.

Now we know that we need to ignore white spaces and comments, that can be done easily, hence we will directly jump to handling the instructions.
##### Translating A-instructions

An A-instruction is of type `@value` where value is a non-negative decimal constant or a symbol (we will deal with them later).

We need to convert this decimal constant to a `15-bit` binary constant and then out machine code for this instruction will be `0valueInBinary`.
##### Translating C-instructions

The structure of a C-instruction is `dest=comp;jump`.

Now assuming that we are able to convert the string and get the three parts i.e. the `dest`, `comp` and `jump` separately. Then we just need to find the binary code for each of the instruction, which will be a simple lookup in the language specification.

We can concatenate these codes to construct a binary string which will be our machine instruction.

For example consider the C-instruction: `MD=D+1`. Then separating out the parts we see that `dest=MD`, `comp=D+1` and `jump=null`. Every C-instruction starts with `111` and adding codes of respective parts we get final binary instruction as `1110011111011000`.

![[Pasted image 20250215190831.png]]

### Assembly Process: Handling Symbols

To handle symbols, first thing that we need is a symbol table, in which we can store symbol and address pair and lookup if some symbol is present or not.

Handling symbols happen in the following steps:

- **Handling Predefined Symbols**: Before the start of the assembly process i.e. before starting the translating process, we initialise the symbol table with all of the predefined symbols. In hack language there are 23 predefined symbols as shown.

![[Pasted image 20250215223911.png]]

- **Handling Label Symbols:** The next thing in the process is to handle label symbols. The syntax for label symbols is `(XXX)` i.e. they start with `(` followed by label symbol and then `)`. When label symbols are defined, we store in the symbol table the address of instruction below this label symbol.
	- We handle label symbols in the first pass of the assembly code, we find all label declarations and find the instruction of instruction below it and then store this pair in symbol table.

- **Handling Variables:** We handle variables in the second pass of the symbol table. Whenever we see a variable declaration, then we add it to our symbol table starting with address 16 (because address `0 to 15` are already taken).
	- When we see an A-instruction which has a symbol after `@`, then we lookup for this symbol in symbol table, if it is not found, then we say that this is declaration of a variable.

### Implementation

Below is an implementation of the assembler in python.

```python
class HackAssembler:
    def __init__(self):
        self.dest_table: dict[str, str] = {
            "null": "000",
            "M": "001",
            "D": "010",
            "MD": "011",
            "A": "100",
            "AM": "101",
            "AD": "110",
            "AMD": "111",
        }
        self.jump_table: dict[str, str] = {
            "null": "000",
            "JGT": "001",
            "JEQ": "010",
            "JGE": "011",
            "JLT": "100",
            "JNE": "101",
            "JLE": "110",
            "JMP": "111",
        }
        self.comp_table: dict[str, str] = {
            "0": "0101010",
            "1": "0111111",
            "-1": "0111010",
            "D": "0001100",
            "!D": "0001101",
            "-D": "0001111",
            "D+1": "0011111",
            "D-1": "0001110",
            "A": "0110000",
            "!A": "0110001",
            "-A": "0110011",
            "A+1": "0110111",
            "A-1": "0110010",
            "D+A": "0000010",
            "D-A": "0010011",
            "A-D": "0000111",
            "D&A": "0000000",
            "D|A": "0010101",
            "M": "1110000",
            "!M": "1110001",
            "-M": "1110011",
            "M+1": "1110111",
            "M-1": "1110010",
            "D+M": "1000010",
            "D-M": "1010011",
            "M-D": "1000111",
            "D&M": "1000000",
            "D|M": "1010101",
        }
        self.predefined_symbols: dict[str, int] = {
            "R0": 0,
            "R1": 1,
            "R2": 2,
            "R3": 3,
            "R4": 4,
            "R5": 5,
            "R6": 6,
            "R7": 7,
            "R8": 8,
            "R9": 9,
            "R10": 10,
            "R11": 11,
            "R12": 12,
            "R13": 13,
            "R14": 14,
            "R15": 15,
            "SCREEN": 16384,
            "KBD": 24576,
            "SP": 0,
            "LCL": 1,
            "ARG": 2,
            "THIS": 3,
            "THAT": 4,
        }
        self.symbol_table: dict[str, int] = {}
        self.lines: list[str] = []

    def resolve_labels(self):
        result: list[str] = []
        for line in self.lines:
            if line.startswith("("):
                # current line is a label, storing it in the symbol table
                label_name = line[1:-1]
                self.symbol_table[label_name] = len(result)
            else:
                result.append(line)

        self.lines = result

    def resolve_variables(self):
        next_free_address = 16
        for line in self.lines:
            if line.startswith("@"):
                variable_name = line[1:]
                # if it is a integer or already present in symbol table, we continue
                if variable_name.isdigit():
                    continue
                elif variable_name in self.symbol_table:
                    continue

                # a variable seen for the first time
                self.symbol_table[variable_name] = next_free_address
                next_free_address += 1

    def remove_whitespaces_comments(self):
        result: list[str] = []
        for line in self.lines:
            # removing any comment in the line
            comment_index = line.find("//")
            if comment_index != -1:
                line = line[:comment_index]

            # removing white spaces from the ends
            line = line.strip()

            # after removing comment and white spaces, if still there is some text,
            # then it is the instruction or label, so we store it
            if len(line):
                result.append(line)

        self.lines = result

    def get_val_in_binary(self, value: int) -> str:
        result = ""
        while value > 0:
            result += str(value % 2)
            value //= 2

        if len(result) > 15:
            result = result[:15]
        else:
            while len(result) < 15:
                result += "0"

        return result[::-1]

    def get_dest(self, instruction: str) -> str:
        try:
            dest = "null"
            indx = instruction.find("=")
            if indx != -1:
                dest = instruction[:indx]

            return self.dest_table[dest]
        except Exception as e:
            print(
                f"Error occured in get_dest, instruction: {instruction} and error: {e}"
            )

    def get_comp(self, instruction: str) -> str:
        try:
            start = instruction.find("=") + 1
            end = len(instruction)
            if instruction.find(";") != -1:
                end = instruction.find(";")

            comp = instruction[start:end]

            return self.comp_table[comp]
        except Exception as e:
            print(
                f"Error occurret in get_comp, instruction: {instruction} and error: {e}"
            )

    def get_jump(self, instruction: str) -> str:
        try:
            jump = "null"
            indx = instruction.find(";")
            if indx != -1:
                jump = instruction[indx + 1 :]

            return self.jump_table[jump]
        except Exception as e:
            print(
                f"Error occurred in get_jump, instruction: {instruction} and error: {e}"
            )

    def assemble(self, code_str: str) -> str:
        # initializing symbol table
        self.symbol_table = copy(self.predefined_symbols)

        self.lines = code_str.split("\n")

        self.remove_whitespaces_comments()

        self.resolve_labels()

        self.resolve_variables()

        machine_instructions = []
        for line in self.lines:
            if line.startswith("@"):
                value = line[1:]
                if value.isdigit():
                    value = int(value)
                elif value in self.symbol_table:
                    value = self.symbol_table[value]
                else:
                    raise Exception(
                        f"value {value} is not a number and not present in symbol table"
                    )
                instruction = "0" + self.get_val_in_binary(value)
            else:
                d = self.get_dest(line)
                c = self.get_comp(line)
                j = self.get_jump(line)
                instruction = "111" + c + d + j

            machine_instructions.append(instruction)

        return "\n".join(machine_instructions)


assembler = HackAssembler()

with open("./max/Max.asm", "r") as f:
    code_str = f.read()
    machine_code = assembler.assemble(code_str)

with open("Max.hack", "w") as f:
    f.write(machine_code)
```
