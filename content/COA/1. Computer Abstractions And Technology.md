### 1.1 Introduction

- **Computers** are a rapidly evolving product of the information technology industry, contributing ~10% of the U.S. GDP. Progress has been driven by **Moore’s Law**, with constant innovation replacing previous breakthroughs.
    
- Computing has fueled the **Information Revolution**, joining the Agricultural and Industrial Revolutions, greatly expanding human capability in science, industry, and daily life.
    
- Every **10× improvement in cost/performance** enables new applications once impractical. Examples:
    
    - **Automobiles** – computer control for efficiency, safety, pollution reduction.
        
    - **Cell phones** – global communication access.
        
    - **Human Genome Project** – affordable genetic mapping for personalized medicine.
        
    - **World Wide Web & Search engines** – transforming information access.
        
- Future possibilities: augmented reality glasses, cashless society, self-driving cars.

#### Classes of Computing Applications

1. **Personal Computers (PCs)** – Focus on good performance for single users at low cost, running third-party software.
    
2. **Servers** – Handle large workloads for multiple users, accessed via networks; range from low-cost file servers to **supercomputers** (tens of thousands of processors, used for large-scale scientific problems).
    
3. **Embedded Computers** – Largest class; built into other devices (cars, appliances, airplanes) to perform specific tasks with strict cost/power limits and high reliability.

#### The Post-PC Era

- Rise of **Personal Mobile Devices (PMDs)** – smartphones, tablets; portable, wireless, app-based, touch or voice input; replacing PCs in many uses.
    
- **Cloud Computing** – large data centers (**Warehouse Scale Computers, WSCs**) hosting services over the Internet.
    
- **Software as a Service (SaaS)** – software delivered via the Internet (e.g., search engines, social media), often with part of the application on PMDs and part in the cloud.

### 1.2 Eight Great Ideas in Computer Architecture

Below we list the eight great ideas that computer architects have invented in the last 60 years of the computer design. These ideas are so powerful that they have lasted long after the first computer that used them.

*  **Design for Moore's Law:** The one constant for computer designers is rapid change, which is largely driven by Moore's Law. It states IC resources double every 18-24 months. As computer designs can take several years, the resources available per chip can easily double or quadruple between the start and the finish of the project. Hence the architects must anticipate where the technology will at the finish of the project rather than design for where it starts.
    
* **Use Abstraction To Simplify Design:** Both architects and programmers had to invent techniques to make themselves more productive. Otherwise the design time would grow as dramatically as resources grew by Moore's Law. A major productivity technique for hardware and software is to use abstractions to characterize the design at a different levels of representation. Lower level details are hidden are hidden to offer simpler model at higher levels.
    
* **Make The Common Case Fast:** Making the common case fast tend to enhance performance better than optimizing for the rare case. Ironically the common case is usually simpler than the rare case and hence is usually easier to enhance. This only implies given that one knows what the common case is which is only possible with careful experimentation and measurement.
    
* **Performance Via Parallelism:** Since the dawn of computers, computer architects have offered designs that get more performance by computing operations in parallel. 
    
    ![[ChatGPT Image Aug 15, 2025, 05_19_36 PM.png]]
    
* **Performance Via Pipelining:** A particular pattern of parallelism is so prevalent in computer architecture that it merits its own name: pipelining. This is basically designing the cpu in such that instructions overlap i.e. instead of performing an instruction fully before performing next one, cpu divides the execution process into stages, as soon as an instruction leaves a stage, the next instruction can enter this state. This means all parts of the cpu can be kept busy at all times.
    
* **Performance Via Prediction:** Following the saying that it can be better to ask for forgiveness than to ask for permission, the next great idea is prediction. In some cases, it can be faster on average to guess and start working rather than wait until you know for sure, assuming that the mechanism to recover from a misprediction is not too expensive and your prediction is relatively accurate.
    
* **Hierarchy Of Memories:** Programmers want memory to be fast, large and cheap, as memory speed often limits the performance, capacity limits the size of problems that can be solved, and the cost of memory is often the majority of the cost in a computer. Architects have found that they can address these conflicting demands with a hierarchy of memories. With the fastest, smallest and the most expensive memory per bit at the top of the hierarchy and the slowest, the biggest and the cheapest memory per bit at the bottom of the hierarchy. Cache give the programmer an illusion that the main memory is as fast as the top of the hierarchy and nearly as cheap and big as the bottom of the hierarchy.
    
* **Dependability Via Redundancy:** Computers not only need to be fast, then need to be dependable also. Since any physical device can fail redundant components are often included so that they can take over when failure occurs and help detect failures.

### 1.3 Below Your Program

A typical application in todays computer like a word processor or a large database system may consist of millions of lines of code and rely on sophisticated software libraries that implement complex functions in support of the application. Later we will see that the computer hardware can only execute extremely simple low-level instructions. To go from complex applications to low level instructions requires several layers that interpret and translated these high level operations into simple low level instructions that the computer understands. This is an example of the great idea of abstraction.

![[Pasted image 20250816091827.png]]

The above figure shows these layers of software are organized hierarchical fashion with application software in the outermost right and several systems software sitting in between application software and hardware.

In a real world application software there will be many layers (e.g. Load Balancer - API server - Database - Container). There are many systems software but two of them are the central to every computer and they are the **Operating System** and **Compiler**.

**Operating System:** provides the interface between the user applications and the hardware and provides several variety of services and supervisory functions. Amongst them most important functions are - 
* Handle basic input and output.
* Allocating storage and memory.
* Providing for protected and fair sharing of computer resources among the different application programs using it simultaneously.

**Compilers:** translate high level language instructions into low-level computer instructions. Given how feature rich modern day high level languages are, converting these instructions to a low level instructions is a very complex task.

#### From a High-Level Language to the Language of Hardware

Computers communicate using electrical signals, which are easiest to represent as **on** and **off** states. This gives rise to the computer’s two-symbol alphabet, represented as **0 and 1** in base 2, or **binary numbers**. Each binary digit (bit) is a fundamental unit of information.

Computers follow **instructions**, which are just collections of bits that the hardware can interpret. For example, a particular bit sequence like `1001010100101110` might tell the computer to add two numbers. A key foundation of computing is that both **data** and **instructions** are represented as numbers.

Writing directly in binary was extremely tedious for the first programmers. To make it easier, they created notations closer to human thinking. Initially, these symbolic notations were converted to binary by hand, but this too was inefficient. The solution was to use the computer itself to do the translation, leading to the invention of the **assembler**—a program that converts symbolic instructions into binary machine instructions.

For example:

- Programmer writes: `add A, B`
    
- Assembler translates: `1001010100101110`
    

The symbolic language is called **assembly language**, while the binary version is the **machine language**.

Assembly language was a major improvement, but it still forced programmers to write one line for every machine instruction, requiring them to think like the computer. The real breakthrough came with the invention of **high-level programming languages** and **compilers**, which could translate more abstract, powerful notations into computer instructions. This leap in abstraction allowed programmers to be far more productive and made programming accessible for complex scientific, business, and practical applications.

![[Pasted image 20250816094231.png]]

A **compiler** allows programmers to write instructions in a high-level language, such as simply writing `A + B`. The compiler translates this into assembly language (`add A, B`), and the assembler then converts it into the corresponding binary machine instructions.

High-level programming languages provide three major advantages:

1. **Natural Expression** – They let programmers use English-like words and algebraic notation, making code more readable and closer to human reasoning. Different languages can also be tailored for specific purposes—for example, **Fortran** for scientific computation, **Cobol** for business, and **Lisp** for symbolic processing. Domain-specific languages exist for even narrower fields, such as fluid simulation.
    
2. **Higher Productivity** – Programs can be written with far fewer lines of code compared to assembly, reducing development time and effort.
    
3. **Machine Independence** – High-level programs can run on different computers, since compilers and assemblers handle the translation into each system’s binary instructions.
    

Because of these advantages, programming in assembly language is now rare, with almost all modern software written in high-level languages.

### 1.4 Under The Covers

We have now looked what is below the software in our computers, now lets understand what is below the hardware. The underlying hardware of any computer performs the same basic operations **inputting data, outputting data, processing data and storing data**.

The tasks of inputting, outputting, processing and storing of data are performed by 5 components of a computer. These 5 classic components of a computer are input, output, memory, datapath and control, with the last two sometimes combined and called the **processor**. This organization is independent of the underlying hardware technology that means you can place every piece of every computer, past and present, into one these 5 categories.

#### Through the Looking Glass

The **graphics display** is one of the most fascinating I/O devices, with most modern personal devices using **liquid crystal displays (LCDs)**.

- An LCD does not emit light itself; instead, it controls light transmission. Rod-shaped molecules in liquid form a twisting helix that bends incoming light. When a current is applied, the rods straighten and stop bending the light. Because the liquid crystal layer is sandwiched between two screens polarized at 90°, light passes only if bent.
    
- **Active matrix LCDs** add a tiny transistor switch at each pixel for precise current control, producing sharper images. In color displays, each pixel has three transistor switches—one each for red, green, and blue components—allowing millions of color combinations.
    

The display image is built from **pixels**, the smallest picture elements, arranged in a matrix (bit map). Tablet displays typically range from **1024×768 to 2048×1536 resolution**, with 24 bits per pixel (8 bits each for red, green, and blue).

To display these pixels, computer hardware uses a **frame buffer (raster refresh buffer)**. This memory stores the bit map, and its contents are read at the refresh rate to generate the onscreen image. The challenge in graphics is that the human eye is very sensitive to even small visual differences, requiring accurate representation.

> Ivan Sutherland, “father of computer graphics,” highlighted the immersive potential of displays, from simulating rocket flights to exploring particle physics (1984).

##### Touchscreens

Post-PC devices (tablets, smartphones) replaced the keyboard and mouse with **touch-sensitive displays**, letting users point directly at objects instead of using a mouse.

Most modern touchscreens use **capacitive sensing**:

- Glass is coated with a transparent conductor.
    
- Since humans conduct electricity, touching the screen distorts its electrostatic field, changing capacitance.
    
- This allows detection of multiple touches and gestures, enabling intuitive and interactive interfaces.

The **A5 package** (Figure 1.8) includes two **DRAM memory chips**, each with 2 gibibits, totaling **512 MiB**. Memory stores both running programs and the data they use. Unlike sequential storage (e.g., magnetic tapes), **DRAM (Dynamic Random Access Memory)** allows random access, with equal access time for any location (~50 ns). In 2012, DRAM cost about $5–10 per GB.

Descending further into hardware, inside the processor we find **cache memory**—a small, fast buffer between the processor and DRAM. Cache is built using **SRAM (Static RAM)**, which is faster but less dense and more expensive than DRAM. Together, SRAM and DRAM form two layers of the **memory hierarchy**.

#### Instruction Set Architecture (ISA)

One of the most important abstractions in computer design is the **instruction set architecture (ISA)**, the interface between hardware and the lowest-level software. The ISA defines everything needed to write correct machine-language programs—such as instructions, registers, memory access, and I/O.

For application programmers, the ISA is combined with the operating system interface to form the **Application Binary Interface (ABI)**. The ABI standardizes binary portability, allowing the same programs to run on multiple hardware implementations.

Computer designers distinguish between:

- **Architecture** – the abstract interface (functions).
    
- **Implementation** – the hardware that realizes this interface.

**Big Picture:** Both hardware and software are built in hierarchical layers using **abstraction**, with each layer hiding details from the one above. The ISA is the critical interface between hardware and software, enabling many hardware designs to run identical software.

#### Volatile vs. Nonvolatile Memory

A key limitation of DRAM-based main memory is that it is **volatile**—it forgets everything when power is lost. In contrast, **nonvolatile memory** (e.g., DVDs, flash memory, magnetic disks) retains data without power.

To distinguish between them:

- **Main (Primary) Memory** – volatile memory (typically DRAM), used to hold running programs and data.
    
- **Secondary Memory** – nonvolatile memory, used to store data and programs between runs. Traditionally dominated by **magnetic disks (hard disks)** with large capacity and low cost (~$0.05–0.10/GB in 2012).

In personal mobile devices, **flash memory** is the standard secondary storage. Compared to DRAM, flash is slower but nonvolatile and cheaper per bit. Compared to disks, flash is smaller, more rugged, consumes less power, and is well-suited for portable devices. However, flash has a finite lifetime: each memory cell wears out after **100,000–1,000,000 writes**, so file systems must distribute writes intelligently to prevent early failure.

#### Communicating with Other Computers

In addition to input, computation, display, and storage, modern computers rely on **networks**, which interconnect whole computers to extend computing power through communication. Networks are now so essential that a device without a network interface would be considered incomplete. They provide three major advantages: **communication** (fast information exchange), **resource sharing** (shared I/O devices), and **nonlocal access** (remote use of computers).

Network cost depends on both speed and distance of communication. The most common type is **Ethernet**, which can span up to a kilometer with transfer speeds of up to 40 gigabits per second, making it ideal for a **local area network (LAN)**—a network confined to a building. LANs are interconnected with switches that may also handle routing and security. In contrast, **wide area networks (WANs)** span continents, forming the backbone of the Internet, and typically use optical fibers leased from telecom companies.

Over the past 30 years, networks have become ubiquitous and exponentially faster. In the 1970s, electronic mail was rare, the Internet and web did not exist, and large data transfer often relied on mailing magnetic tapes. LANs were almost nonexistent, and WANs had limited access and capacity. The first standardized LAN (an early Ethernet) had a maximum **bandwidth** of 10 megabits per second shared among many computers, whereas today LANs offer **1 to 40 gigabits per second** usually shared by only a few. Similarly, WAN capacity has grown from hundreds of kilobits to gigabits, expanding from hundreds to millions of connected computers. This explosive growth in deployment and performance has made networking central to the information revolution.

In the last decade, **wireless technology** has further reshaped communication, fueling the post-PC era. The development of low-cost radios using CMOS (the same technology as memory and processors) made wireless cheap and widespread. Current IEEE 802.11 standards support **1 to nearly 100 megabits per second**, though unlike wired networks, wireless requires all users in an area to share the airwaves.

### 1.5 Technologies for Building Processors and Memory

Processors and memory have advanced rapidly as computer designers continuously adopted the latest electronic technologies to improve performance.  

![[Pasted image 20250816142700.png]]

Figure 1.10 shows the evolution of technologies used in computers with their relative performance per unit cost. Since such technologies determine what computers can achieve and how quickly they evolve, all computer professionals should understand the basics of **integrated circuits (ICs)**.

A **transistor** is an electric on/off switch, and the IC combined dozens to hundreds of transistors into one chip. Gordon Moore’s prediction of continuous doubling of resources referred to the growth in transistors per chip. With millions of transistors integrated, this became known as **very large-scale integration (VLSI)**.

![[Pasted image 20250816142746.png]]

Figure 1.11 shows the growth in **DRAM capacity** since 1977, where the industry quadrupled capacity every three years (about 60% per year) for decades, leading to over a 16,000-fold increase. Recently, the rate slowed to doubling every two to three years.

The manufacturing of ICs begins with **silicon**, a semiconductor found in sand. By adding materials through chemical processes, silicon can be made into conductors (e.g., copper or aluminum wires), insulators (e.g., plastic sheathing or glass), or switches (transistors). Thus, a VLSI circuit is billions of these combinations in one package.

![[Pasted image 20250816142836.png]]

Figure 1.12 shows the **chip manufacturing process**. It starts with a **silicon crystal ingot** (8–12 inches in diameter, 12–24 inches long), sliced into thin **wafers**. These wafers undergo 20–40 steps where chemicals create the transistors, conductors, and insulators. Today’s ICs have one layer of transistors and 2–8 layers of metal conductors separated by insulators. Wafers are tested, mapped, and then diced into **dies (chips)**. Good dies are bonded into packages and tested again before shipment. For example, one wafer with 20 dies had 17 good ones, giving an **85% yield**.

A **defect** (microscopic flaw in the wafer or patterning) causes die failure. Since perfect wafers are impossible, many dies are produced so only defective ones are discarded. Yield—the percentage of good dies—determines cost efficiency.

![[image-removebg-preview.jpg]]

Figure 1.13 shows a 12-inch wafer of Intel Core i7. It could fit 280 dies at 100% yield, though edge dies are useless. It used **32-nanometer technology**, meaning the smallest features are ~32 nm, with actual transistor sizes usually slightly smaller.

Die size strongly impacts cost since larger dies reduce yield and fit fewer per wafer. To reduce cost, newer process generations shrink transistor and wire sizes, increasing yield and die count. In 2012, 32 nm was typical. Once good dies are found, they are bonded to package I/O pins, tested again, and shipped.

### 1.6 Performance

Assessing computer performance is challenging because of the complexity of modern software and the wide range of hardware optimization techniques. When choosing computers, performance is critical both for buyers and designers, but vendors may present it selectively. Thus, understanding how performance is measured and the limits of those measurements is essential. This section discusses definitions of performance, relevant metrics, their relationships, and the classical processor performance equation.

![[Pasted image 20250816172357.png]]

Defining performance is not straightforward. Figure 1.14, which compares airplanes by speed, range, and capacity, illustrates that performance depends on what is being measured. The Concorde was fastest by speed, the DC-8 had the longest range, and the 747 had the greatest passenger capacity. If speed means “time for one passenger,” Concorde wins; if it means “time for 450 passengers,” the 747 wins. Similarly, computer performance depends on context.

For an individual user, the **faster computer** is the one with lower **response time (execution time)**—the total time from task start to completion, including CPU, memory, I/O, and OS overhead. For a datacenter, the faster system is the one with higher **throughput (bandwidth)**—the number of tasks completed per unit time. Thus, mobile devices are usually optimized for response time, while servers emphasize throughput.

**Throughput vs. Response Time Example:**

1. Replacing a processor with a faster one improves both throughput and response time.
    
2. Adding more processors for independent tasks increases throughput, but not individual response time. However, if workload is heavy and requests queue, improved throughput can also reduce response time.

In this text, the focus is mainly on minimizing response time. Performance and execution time are reciprocals:

- If computer X is faster than Y, execution time on X is shorter.
    
- “X is _n_ times faster than Y” means execution time on Y is _n_ times that on X.  
    **Example:** If A runs a program in 10s and B in 15s, A is 1.5× as fast as B. Equivalently, B is 1.5× slower.

Since performance = 1 / execution time, increasing performance means decreasing execution time. To avoid confusion, we say “improve performance” or “improve execution time.”

**Measuring Performance:**  
The most direct measure is **elapsed time (wall clock time, response time)**—the total time to finish a task including all delays. But since computers are often shared, we also measure **CPU execution time (CPU time)**—the time the CPU actually spends computing for the program, excluding waiting for I/O or running other programs. CPU time has two parts: **user CPU time** (time spent in the program itself) and **system CPU time** (time spent by the OS on the program’s behalf). In this book:

- **System performance** = elapsed time on an unloaded system.
    
- **CPU performance** = user CPU time.

**Program Performance Considerations:**  
Different applications depend on different factors. Server applications may be I/O-bound, making elapsed time more important. Some environments care about throughput, some about response time, and some about both. Improving performance requires identifying bottlenecks (e.g., CPU, I/O, memory) and addressing them.

Designers often think in terms of hardware speed, which is tied to the **clock**. Computers operate in discrete **clock cycles (ticks, periods)**. A clock period is the time per cycle (e.g., 250 ps), and the **clock rate** is its inverse (e.g., 4 GHz). Later, this relationship between cycles and execution time will be formalized.

#### CPU Performance and Its Factors

The most crucial and reliable measure of a computer's performance is the **CPU execution time**—the time it takes for the CPU to run a program. This can be calculated with a fundamental formula that connects it to the processor's clock.

The formula is:

$$
CPU execution time=CPU clock cycles×Clock cycle time
$$

Since clock rate is the inverse of clock cycle time, the formula can also be expressed as:

$$
CPU execution time=Clock rateCPU clock cycles​
$$

This means a hardware designer can improve performance by either reducing the total number of clock cycles a program needs or by decreasing the length of each clock cycle (i.e., increasing the clock rate). However, these two factors often involve a trade-off; for instance, design changes that reduce the number of required clock cycles might lead to an increase in the clock cycle time.

#### Instruction Performance and CPI

To better understand what determines the total number of clock cycles, we need to consider the program's instructions. The total clock cycles can be seen as the product of the number of instructions and the average number of cycles each instruction takes.

This introduces the concept of **CPI (Clock Cycles Per Instruction)**, which is the average number of clock cycles required to execute one instruction for a given program. Because different types of instructions can take different amounts of time, CPI is an average.

The formula for total clock cycles is:
$$
CPU clock cycles=Instruction count×CPI
$$

CPI is a useful metric for comparing different implementations of the same instruction set architecture, as the instruction count for a specific program will be identical on both implementations.

#### The Classic CPU Performance Equation

By combining the formulas above, we get the classic CPU performance equation, which provides a complete picture by linking execution time to three key factors:

$$
CPU time=Instruction count×CPI×Clock cycle time
$$

Or, using the clock rate:

$$
CPU time=Clock rateInstruction count×CPI
$$

This equation is powerful because it separates the three critical factors affecting performance:

1. **Instruction Count (IC):** The total number of instructions executed by the program.
    
2. **Cycles Per Instruction (CPI):** The average number of clock cycles per instruction.
    
3. **Clock Cycle Time (or Clock Rate):** The duration of a single clock cycle.

It is dangerous to assess performance by looking at only one of these factors. For example, a code sequence with a lower instruction count might not be faster if its instructions have a higher average CPI, leading to more total clock cycles. **The only complete and reliable measure of performance is the total execution time.**

#### What Affects Performance?

The performance of a program is influenced by a combination of software and hardware components, each affecting the terms in the performance equation.

- **Algorithm:** Primarily determines the **instruction count** and can also influence the **CPI**. A different algorithm might require fewer operations or use instructions that are inherently faster or slower.
    
- **Programming Language:** Affects the **instruction count** based on how its statements are translated into machine code. It can also impact **CPI**, as certain language features might rely on more complex, higher-CPI instructions.
    
- **Compiler:** The compiler's efficiency directly impacts both the **instruction count** and the **CPI** by deciding how to translate the source code into optimized machine instructions.
    
- **Instruction Set Architecture (ISA):** This has the broadest impact, affecting **all three factors**: the instruction count needed for a task, the CPI for those instructions, and the processor's achievable clock rate.

#### Additional Considerations

- **IPC (Instructions Per Clock Cycle):** Some modern processors can execute multiple instructions in a single clock cycle. For these systems, performance is sometimes measured by IPC, which is simply the inverse of CPI (IPC=1/CPI). An IPC of 2 means the CPI is 0.5.
    
- **Variable Clock Rates:** Modern processors can adjust their clock rates dynamically (e.g., Intel's Turbo Mode) to either save power or provide a temporary performance boost. In such cases, performance calculations should use the _average_ clock rate over the program's execution.
